`tests/scene-display-performance-regression.mjs` 在 1,500 个对象、2 个分类全部折叠的合成目录下对比：

| 指标 | 原实现 | 修改后 |
| --- | ---: | ---: |
| 初次创建的 DOM 元素 | 12,019 | 19 |
| 初次及连续 20 次刷新累计创建的 DOM 元素 | 270,380 | 380 |

该结果衡量折叠目录的控件创建与监听开销，不是用户原项目 GPU 帧率。模型几何、画质和倾覆计算精度保持原实现。

## 文件语义

删除受控文件失败时，已经持久化的删除标记继续阻止复活，并显示待清理状态供重试。普通附件及机械资料均可在重开后恢复清理入口。视频浏览器缓存以服务端已删除录像 ID 对账，避免关闭浏览器后失去清理依据。

机械场景实例的移除保留原业务资源与关联证书，内置公共模型不删除；资料自身通过“删除文件”清理。业务“作废”、场景“隐藏”、关系“解除关联”维持既有语义。共享引用中的附件会拒绝物理删除。外部原始导入文件不被删除；可追溯的平台副本和衍生缓存会清理。旧无归属转换缓存不按猜测删除。

## 验证边界

完整应用演练采用隔离数据库、合成吊机和样例 PDF，不使用用户原项目模型、视频或正式文件。用户 Windows 设备的大体量场景流畅度、文件占用行为和 SketchUp/ArcPy 本机能力仍需本机验收。代码交付不等同于更新用户原电脑，部署流程见 `CODEX_LOCAL_DEPLOY_OPERATIONS.md`。
