## 4. 先建立唯一模型坐标与几何版本

### 4.1 规范化模型

优先从 ContextCapture 导出带纹理的项目 ROI 网格和明确地理参考，再转换为局部 ENU GLB/分块 GLB。实际只能取得 3D Tiles 时，实现并验证离线转换器：

1. 累乘根与子节点变换，处理内容/实例变换、RTC、glTF 轴向；根据实际文件格式核对规范。
2. 每个区域选择一个完整且固定的几何层级，正确处理 ADD/REPLACE 细化关系，避免父子瓦片重复叠加。
3. 保留 UV、纹理、材质类别、alpha test 和双面语义；缺纹理或缺几何必须进入报告。
4. 对转换前后可追踪顶点/特征点做坐标比对，给出包围盒、变换链和误差。
5. 首次 ROI 覆盖稳定视频片段及沿途可见对象，并包含对其产生遮挡的外围几何。随后扩展至整段视频。

`geometry_version` 根据实际顶点、三角形、变换、LOD、材质遮挡规则和 mask 生成内容指纹。定位参考、源相机深度、最终融合都引用同一版本；变化后使相关缓存失效。初版禁止观察相机和源相机独立选择不同 LOD。

如果需要减面，先生成固定的新版本，测量相对原网格误差，再用该版本重新生成参考库。不得定位用精细模型、显示时换未经验证的简化模型。

### 4.2 坐标契约

- 世界坐标 `scene`：局部 ENU，X 东、Y 北、Z 天，单位米。
- 持久化 `T_ecef_from_scene` 及逆变换，原点经纬高注明 WGS84 椭球高及来源；未知高程基准不得标成已核定。
- CPU 地理转换使用双精度，GPU 使用局部米制坐标，避免直接用百万米级 ECEF 单精度计算局部投影。
- 光学相机采用 OpenCV 约定：x 右、y 下、z 前。

唯一外参定义：

```text
X_camera = R_camera_from_scene * X_scene + t_camera_from_scene
C_scene = -transpose(R_camera_from_scene) * t_camera_from_scene
```

交换矩阵采用 4×4 行主序数组、列向量左乘；最后一行为 `[0,0,0,1]`。各语言适配器显式转换存储布局，不能直接把数组传给布局不同的 API。界面可以显示欧拉角，核心只传矩阵/四元数。

Three.js 视图坐标从上述光学坐标显式转换：`S = diag(1,-1,-1,1)`，`T_three_view_from_scene = S * T_camera_from_scene`。不要分散使用若干 yaw/pitch/roll 加减 90° 的补丁。

## 5. 统一视频、内参、畸变和时间

### 5.1 时间与图像身份

用 FFmpeg/PyAV 按真实 PTS 解码，保留原始 time_base 与整数 PTS，不以 `frame_index / 30` 推算时间。保存旋转、裁切、缩放、代理重编码与原视频的帧映射。

浏览器播放使用经验证的 H.264 等可解码代理；代理的呈现时间可以不同，但必须能唯一映射回原帧。`requestVideoFrameCallback` 的呈现时间经过映射取得对应位姿，不以墙钟或 `setInterval` 推进遥测。

最终相机位姿绑定产生该位姿的视频图像及原始 PTS。遥测未知延迟仅影响候选初值，不能继续左右已经视觉求解出的相机。遥测时差估计作为独立诊断，不在第一版与所有相机参数一起任意拟合。

### 5.2 图像空间

第一版统一采用：**原始解码图 → 去畸变/裁切/缩放 → rectified 图像及 K_rect**。

定位、独立检查点、源深度和视频采样全部针对 rectified 图像。原图点通过记录的映射转换；不得在最终 shader 中再次去畸变。

标定记录至少包含：原画幅、K_raw、畸变模型和 D_raw、K_rect、输出画幅、有效 ROI、镜头/变焦适用区间、图像映射版本、来源与置信状态。

内参获取顺序：已有同镜头同模式真实标定 → 新标定采集 → 在当前素材上受约束的多帧联合估计。缺少标定时可从历史估算 K、零畸变初始化，但状态必须是 `estimated`，不能据此宣称已消除镜头畸变。

先固定内参求姿态；随后在具有视角/距离变化、空间分布充分的关键帧上逐步开放共享 fx/fy、必要的低阶畸变。主点和更多畸变项只有在独立误差与可观测性支持时开放。不要为每帧自由优化一套 K，也不要同时放开焦距、全部畸变、所有姿态、时间偏移和模型坐标。

若数据近似平面、视角变化不足或存在未知电子防抖/动态裁切，明确标注不可辨识，提供补充标定所需数据。滚动快门只在基础几何通过、残差呈现可重复的逐行运动模式后单独建模，不先堆叠新参数。

更新标定后重新生成对应 rectified 图像、特征和位姿，或完成数学上等价且经验证的重映射。不得让缓存混用标定版本。

### 5.3 像素约定

左上像素中心是 `(0,0)`；连续图像边界是 `[-0.5,W-0.5] × [-0.5,H-0.5]`。

```text
u = fx * Xc / Zc + cx
v = fy * Yc / Zc + cy
```

纯缩放须遵循实际采样器的像素中心关系；例如中心对齐缩放的主点为 `cx' = sx*(cx+0.5)-0.5`，裁切还要减去裁切起点。不能只改 fx/fy 而忽略主点。特征库内部缩放也必须返回原处理图坐标或明确映射。

构造 Three.js 离轴视锥时使用 K_rect。设近裁面 n：

```text
left   = n * (-0.5 - cx) / fx
right  = n * (W - 0.5 - cx) / fx
bottom = -n * (H - 0.5 - cy) / fy
top    = n * (cy + 0.5) / fy
```

视锥不能再被 UI 的 HFOV/VFOV 默认值覆盖。统一纹理存储契约为“图像顶行位于纹理 t≈1”，对应采样 `s=(u+0.5)/W`、`t=1-(v+0.5)/H`。不同上传源显式适配该布局，分别验证 HTML 图像、Canvas、ImageBitmap/WebCodecs 路径；不能机械设置 flipY 后再叠加翻转。若某适配器实际使用顶行位于 t≈0 的纹理，必须记录其布局并使用 `t=(v+0.5)/H`，不得套用前式。GPU readback 也应显式处理行顺序。使用四角不同颜色的测试图验证，再通过主点和非等焦距测试。

## 6. 从模型构建可定位的参考库

使用规范模型在候选相机处渲染参考视图。每个参考视图必须保存：RGB、K_ref、相机矩阵、camera-Z 米制深度、有效 mask、三角面 ID、几何与材质版本。

这里的深度是 `Z_camera`，不是射线长度、NDC 深度、逆深度或经打包后未解释的颜色。

生成策略：

1. 遥测确定大致区域和朝向，按其真实不确定性建立可配置的平移、旋转、高度候选范围；未知基准不能直接收缩成精确高度。
2. 初次围绕稳定的约 10.01 秒帧建立候选，采用较低分辨率和粗间隔搜索；有可靠定位后在其附近加密。
3. 参考库沿航迹扩展，并覆盖相邻视角，采用粗检索后局部匹配；缓存特征，限制每帧候选数量并输出耗时。
4. 参考渲染不添加原模型没有的“增强纹理”或虚构建筑。颜色校正可用于匹配，原始参考图和处理参数必须保留。

参考像素 `(ur,vr)` 的 3D 回投：

```text
X_ref_camera = depth_z_m * inverse(K_ref) * [ur, vr, 1]
X_scene = R_ref_camera_from_scene^T * (X_ref_camera - t_ref_camera_from_scene)
```

亚像素关键点优先以已知相机射线和对应网格求交获得精确 3D 点。使用深度插值时必须验证邻域属于同一连续表面，拒绝深度断裂和跨三角面不连续插值。CPU 射线求交抽样复核参考深度。

建模原照片和完整定向相机/观测点若可导出，可增加真实照片参考库以改善外观差异；这是兼容输入，不是从 ATReport 中凭空恢复的数据。不能把 hloc 安装成功当成已完成网格参考库适配。

## 7. 单帧定位：先产生可信的 2D–3D 对应

实现 ALIKED + LightGlue；同时保留 SIFT、双向检查和比例过滤的 CPU 基线，便于判断问题在学习模型、依赖还是几何。权重可离线缓存；无 CUDA 时可以降低分辨率/关键点数量离线运行，不承诺实时速度。

处理步骤：

1. 读取 rectified 视频帧，检索候选参考视图。
2. 提取/匹配局部特征，记录匹配分数与参考来源。
3. 利用参考深度/网格射线生成 `video_pixel ↔ scene_XYZ`。
4. 去除无效深度、轮廓、严重掠射、水面、树冠、运动目标、重复/冲突对应。同一视频点来自多个参考时检查世界点一致性，不能重复计票提高内点数。
5. `solvePnPRansac` 解算世界到相机外参，使用内点进行 `solvePnPRefineLM` 等精修。rectified 图像使用 K_rect 和零畸变；原图模式如用于标定诊断，必须显式传 K_raw/D_raw。
6. 检查正深度、残差、空间覆盖、共面退化、姿态候选歧义及相邻帧一致性。不要只按匹配数选结果。
7. 输出 CPU 重投影图、内外点、每点残差、相机矩阵和质量状态。

可采用的初始运行参数：1080p 等效 RANSAC 阈值 3 像素、置信度 0.999、迭代上限 5000；初步合格要求至少 30 个去重内点、覆盖 4×3 图像网格中的至少 6 格。它们是需要在本素材上验证的初始工程参数，不是验收结论；调整必须留记录，不能降低阈值定义来伪造成功。

主要对应都落在平面时，可以验证该平面的定位，但不能外推为立面与楼顶也已准确。建筑场景需增加不同深度/高度的证据，检查退化与多解。

自动匹配失败时依次检查真实纹理是否完整、候选视角、图像尺度、遮挡与时相变化。允许在少量关键帧中人工选取 8–12 对明确的模型/视频点作为初始锚点，并保留原始证据；后续仍应建立逐帧视觉轨迹。禁止将一次人工配准转换成整段统一偏移后就宣布完成。

## 8. 多关键帧优化、连续跟踪与失败状态

### 8.1 多帧优化

固定 CC 世界点，只优化各关键帧 SE(3) 位姿，并按第 5 节逐步优化同镜头状态下共享内参。代价采用鲁棒重投影误差；遥测、速度和姿态平滑只能作为权重明确的软约束。

必须分开两种求解：固定标定的姿态优化使用 rectified 像素、K_rect、D=0；优化 K_raw/D_raw 的共享标定回到保存的原始 raw 像素观测，使用包含前向畸变的原始相机模型。不能在固定的 rectified 像素上自由优化原始畸变系数。匹配产生的 rectified 点需通过该版本映射取得 raw 观测并留存。

```text
pose-only: sum rho( || project(K_rect, 0, T_i, X_j_fixed) - pixel_rect_ij ||^2 )
calibration: sum rho( || project(K_raw, D_raw, T_i, X_j_fixed) - pixel_raw_ij ||^2 )
  + optional weak prior terms
```

不能通过移动模型点降低误差而破坏地理锚定。先分别运行无遥测约束与弱约束结果，确认错误高度没有压过真实图像证据。输出参数变化、残差空间分布及保留帧结果。标定更新后重新生成 rectified 图像、特征和位姿并复验；真实检查点保留 raw 原始标注，经新标定映射获得当前 rectified 检查坐标。

约 10.01、30、60、90、114 秒为初始锚定帧，另覆盖开头云台快速变化、转向和遮挡变化。0 秒可能含较多天空，必须评估可定位性，不能为满足固定表格强行标为成功。

### 8.2 连续轨迹

在关键帧上锚定真实模型点，通过双向光流或局部特征跟踪得到连续 2D 观测，再解每帧 PnP；周期性执行模型重定位并在质量下降时立即触发。新增点必须回到模型几何，不能仅凭累计 2D 变换漂移。

初版可每秒选择 1–2 个重定位关键帧，在快速运动/俯仰变化处加密；最终每个播放帧都必须有对应的有效位姿或明确失效状态。插值只能用于短缺口、具有相邻可靠约束且通过误差检查的情况，必须记录 provenance，不能跨长失定位区间无条件补轨迹。

| 状态 | 定义 | 显示行为 |
|---|---|---|
| `LOCALIZED` | 当前帧通过模型重定位和质量检查 | 可融合 |
| `TRACKED` | 基于已锚定三维点跟踪并通过几何检查 | 可融合，保留误差证据 |
| `DEGRADED` | 约束或覆盖不足，结果未达到融合门槛 | 默认关闭视频投影，显示状态 |
| `LOST` | 无可靠相机或输入不完整 | 显示模型底纹，触发重定位 |

质量不得只用学习匹配分数。至少统计内点数/比例、图像与深度分布、残差、跟踪存活和退化状态。记录全视频成功帧数、失败时段及原因，不能只导出效果最好的几帧。

## 9. 新投影器：直接投到统一三角网

### 9.1 源相机深度

用已验收相机、K_rect 与规范模型，从视频相机方向生成独立 RenderTarget：

- 首选 `R32F` 颜色附件存线性 camera-Z 米值，硬件深度附件决定最近表面；清除值 0 表示无效。
- MVP 的源深度 FBO 尺寸固定等于 rectified 视频的 W×H，使用相同 K_rect。以后改变深度分辨率时，必须独立记录 K_depth、深度尺寸及精确像素映射，不能把视频 K 原样用于任意方形 FBO。
- 启动时验证 WebGL2、浮点颜色附件能力、FBO 完整性和已知距离读写。能力不足则明确不支持该精确融合模式，不能静默回退到平面贴图。
- nearest 采样、无 mipmap；关闭混合、polygonOffset、日志深度和该深度 pass 的 MSAA。
- 深度 pass 与显示 pass 使用相同 opaque/alpha-test 规则；近远裁面覆盖全部相关遮挡体。
- 使用源相机视锥内完整的 ROI 几何，不使用观察者视角的可见物体列表代替。
- 提供深度、有效区、表面类别/ID 和拒绝原因的诊断输出。

### 9.2 表面融合

对观察者实际看到的每个模型片元，将其 `X_scene` 经视频相机矩阵投到 rectified 视频像素。只有位于源视野内、有效图像范围内、相机前方、可接收区域且未被遮挡时才采样视频，否则使用原模型纹理。

观察者相机只决定从哪里看模型，不参与世界点到视频像素的映射。同一世界点在任意观察角度下都应对应同一源像素。

源视频已经包含照明。投影部分避免被模型照明再次调暗；先在线性色彩空间混合，再统一输出，防止错误 gamma 混合。几何诊断模式使用 alpha=1，不能用低透明度掩盖重影。

### 9.3 遮挡采样的具体要求

简单比较模型点 Z 与最近 texel 的 Z，会在斜面和轮廓产生采样误差。MVP 使用保守遮挡判断：

1. 在连续同一表面内，以接收三角形的真实平面，将预期深度换算到被采样 texel 中心对应的射线上，再与该 texel 深度比较。具体在源光学相机系写平面 `n·X+d=0`，采样中心射线为 `q=inverse(K_depth)*[u_texel,v_texel,1]`，则预期 camera-Z 为 `-d/(n·q)`。MVP 中 K_depth=K_rect。拒绝近平行射线、非正深度、超裁面和跨真实轮廓的外推；其他局部平面实现须通过同等验证。
2. 使用几何面法线，不能把平滑着色法线当成三角形平面。关键步骤不依赖在分歧控制流之后调用的导数。
3. 根据邻接关系、几何法线与深度判断真实表面不连续，拒绝跨断裂补偿。不同 triangle ID 本身不是拒绝条件，相邻连续三角面不能每条边都挖空；ID 只作为辅助。真实轮廓采取保守收缩，可设置 1–2 个源像素的边界带并单独统计。
4. 数值容差只覆盖浮点、深度量化和离散采样误差，给出推导或实验误差上界；不沿用固定 ±0.35 米或不断放大阈值来填空洞。
5. 用 CPU 三角网射线求交抽样核对“可见但漏投”和“被遮挡却投上”的比例，分别报告。边界带不能无限扩大来优化指标。

模型精度不足或几何不存在时，不能通过深度容差创造真实表面。水面、玻璃反射、植被和移动目标默认不进入可靠定位集；首版精确融合只承诺有可信几何的静态不透明表面。动态目标若在视频中可见但模型中不存在，普通投影无法还原其立体位置，使用 mask 排除或明确显示为低可信内容。

### 9.4 卫星底图与地形

卫星影像提供颜色，地形/网格提供三维几何。需要在新视图展示底图时，将可用影像贴到坐标一致的地形网格上；倾斜模型区域优先由模型接收视频，避免重复地面引起 z-fighting。底图与地形的覆盖、分辨率、数据基准和使用条件写入清单。

只有椭球或平面而没有真实地形时，可以作为导航背景，但不能把它的地形精度视为已知。建筑影像不能整体压在平面上作为本任务完成。

## 10. 视频帧、相机和深度原子绑定

每次提交给 renderer 的是不可拆分的帧包：

```text
ProjectionFrameBundle
  source_video_hash, original_frame_id, original_pts, time_base
  proxy_frame_id / proxy_pts mapping
  rectified_frame_texture, image_size, valid_image_mask
  camera_profile_id, calibration_version, K_rect
  T_camera_from_scene
  pose_status, pose_quality, pose_provenance
  scene_id, geometry_version
  source_depth_texture, source_depth_frame_id
```

采用双缓冲：视频纹理、姿态、标定、几何与源深度全部匹配后一起切换。显式抓取并上传对应帧，不能让一个自动更新的 HTMLVideoElement/VideoTexture 在深度和姿态未提交时独自前进。

新帧准备不及时时可暂留上一完整帧并显示缓冲状态，或关闭融合；不能组合新视频与旧相机。观察者转动不必重新计算源深度，源相机/内参/几何变化才使它失效。跳转时间轴必须清理旧的异步任务，避免完成较晚的旧帧覆盖新帧。

## 11. 持久化数据契约

| 产物 | 最少内容 |
|---|---|
| `scene_manifest.json` | 模型来源、几何/纹理哈希、坐标原点与变换、高程依据、ROI、LOD、接收类别、缺失区 |
| `video_manifest.json` | 文件哈希、原始 PTS/time_base、画幅、方向、代理映射、裁切缩放与镜头状态 |
| `camera_profiles.json` | K_raw/D_raw、K_rect、图像尺寸/ROI、来源、有效时间段、估计/标定状态 |
| `references/manifest.jsonl` | 参考视图 ID、RGB/深度/mask/面 ID 路径、K、位姿、几何版本 |
| `correspondences/*.npz` | 视频像素、参考像素、世界 XYZ、来源面、得分、内外点、残差和去重标识 |
| `poses.jsonl` | 每帧身份/PTS、profile、世界到相机矩阵、状态、来源、质量和几何版本 |
| `checkpoints.json` | 独立真实检查点、raw 原始像素与当前 rectified 映射、3D 坐标、标注依据、不确定度、帧 ID、用途 |

Schema 中禁止 NaN/Infinity，明确单位、矩阵方向和数组顺序。读取时校验模型、视频与标定身份，发生不一致直接报错，不静默复用旧结果。

## 12. 分阶段执行与放行条件

| 阶段 | 工作 | 放行条件 |
|---|---|---|
| A0 新框架 | 保护工作区、数据探测、契约与独立页面、日志/启动器 | 本机可以启动新模块并报告真实输入和能力 |
| A1 场景规范化 | 完整纹理 ROI、固定几何版本、ENU/ECEF 转换 | 转换前后可追踪点一致，缺失与基准明确 |

| A4 多帧定位 | 其他时刻、共享标定、退化检查 | 不同时间/高度表面独立误差达标，无单帧偏移冒充全局 |

A1/A2 的合成数学工作可与定位接口并行。A3 使用估算内参时可能需要 A4 的多帧共享标定才能达标：取得足够可靠的多帧对应/人工锚点后，允许进入 A3→A4→A3 的标定与复验回路，不要求未经标定的单帧先达到最终精度。A3/A4 尚未达标时继续完成不依赖真实位姿的 renderer 测试，但不得通过 shader 调参宣称真实定位已解决。实景融合放行必须建立在几何和相机独立验收通过之后。

## 13. 验收方法与初始研发目标

### 13.1 把三种误差分开

1. **转换/渲染数学误差**：已知准确相机和合成几何，验证 CPU 投影、GPU 视频像素、源遮挡与矩阵方向。
2. **相机相对模型的配准误差**：真实视频的独立 2D–3D 检查点，不参加定位/标定拟合。
3. **模型对真实地理世界的误差**：需要独立地理控制资料；视频贴到模型准确不能证明模型本身坐标准确。

### 13.2 真实检查点

先在约 10.01 秒选择至少 6 个可确认的独立检查点，尽量覆盖道路、桥面、屋顶、可见立面和图像边缘；另保留拟合点。其他关键时刻同样保留分布合理的检查点。若当前视图没有足够可辨认点，记录不能验收的原因，不编造坐标。

通过工具在视频图上标 2D 点、在模型中拾取同一物理点，保存截图与原始坐标。若利用检查点反复调参，它们成为开发验证集，最终另留新的检查帧/检查点。

初始研发目标以 **1920×1080 等效像素**计：检查点 RMS ≤3 px、P95 ≤6 px、最大误差 ≤10 px；对 4K 按比例换算。目标需要结合模型、像质和标注不确定度评估，它不是当前已达到的结果，也不是无需实测的保证。无法达到时分解残差原因并报告实测值，不擅自改宽阈值后写“通过”。

合成 CPU/GPU 像素位置差目标 ≤0.5 个源像素，排除有明确规则的轮廓带；至少包含偏心主点、fx≠fy、斜面、近墙挡远墙、屋顶立面、不同观察角度和图像四角。遮挡用 CPU 射线真值分别统计误投与漏投，不以“像素颜色变化”判断正确。

### 13.3 连续验收

全视频每帧统计状态；另外固定开头云台变化、中段稳定、遮挡/转向、结尾等连续片段检查，不只展示静止截图。报告：

- 定位覆盖率、按状态分布、失败总时长与最长连续失效；失败原因分组。
- 真实检查点误差，按时间、距离/深度、地面/屋顶/立面和画面区域分组。
- 跟踪漂移、重定位前后跳变及原始/平滑轨迹；平滑不得掩盖持续偏差。
- 源深度有效覆盖、遮挡误投/漏投、轮廓拒绝区域。
- 帧身份/几何版本不一致次数必须为 0。
- 实际硬件、预处理时长、内存、播放 FPS 和帧准备延迟；区分离线求解速度与浏览器回放速度。

第一版可暂以可定位且具有可信静态几何区域的有效帧覆盖率 ≥95% 为待验证目标，但必须同时列出全视频原始覆盖率与预先定义的排除区间。没有总体覆盖结果不能宣布整段稳定。实时帧率待真实硬件评估后另立目标。

配置包含输入路径、场景 ROI、参考搜索范围、初始内参来源、匹配设备、缓存位置、质量阈值和端口。不能把本次 F 盘目录或上传分析包路径硬编码进算法。

实现 Windows 启动入口与日志文件。双击启动前检查环境，失败时保留可读错误及日志路径，避免控制台闪退；正常启动后给出浏览器地址。依赖和模型下载有明确进度、版本、缓存和失败重试信息。

最终至少交付：

1. 可运行的新 `ar_v2` 代码、锁定依赖、示例配置和启动器。
2. 真实模型规范化清单与转换验证报告。
3. 真实视频参考库、对应点和逐帧位姿产物，含版本与来源。
4. 单帧及多帧独立检查点报告、CPU 重投影证据和新引擎效果对照。
5. 全视频连续回放质量报告及已知失败片段。
6. 与旧路线的明确边界、平台接入说明、运行 README、`AR_V2_STATUS.md` 和后续实时化待办。

没有完整模型时，必须明确写“实景验收受阻：缺少实际纹理几何”，给出所需目录/导出格式；完成其余模块和合成验证，但不能标记整项任务完成。没有检查点时同理提供可用标注工具与具体待补清单，不自动生成所谓真实检查点。

## 15. 不允许作为完成依据的做法

- 在旧 renderer 中修改几个姿态、FOV、高度、透明度或深度阈值后改名 V2。
- 把单应性或一个平面四角贴图用于包含明显高差的整幅场景。
- 使用单帧人工修正给整段视频套固定偏移。
- 使用匹配内点的拟合误差代替独立真实检查点误差。
- 用合成场景、静止截图、模型可见、颜色变化或无异常日志宣称实景对齐成功。
- 用错误相机投出的深度自洽性证明相机对真实图像准确。
- 因模型缺失而投到平面，并称为倾斜摄影融合。
- 新帧视频配旧位姿/旧深度，或在失定位时无提示地继续显示精确融合。
- 宣称换用 Three.js 本身会提高定位精度；精度必须来自模型、相机求解和独立验收。
