# 兼容性与回归验收约定

生效日期：2026-11-11。

## 1. 基线及保护范围

**后续开发不得破坏、影响或改变上一已验收版本已经实现的功能。** 用户明确要求的行为变更仅限该需求范围，其余既有能力必须保持兼容。

| 项目 | 已确认基线 |
| --- | --- |
| 运行版本 | v1.2.2 |
| 备份提交 | `60395aae96fc78753cdeef99e8f745e33d0a5903` |
| 对应应用源码提交 | `84300b4dedccc3f0116f03332c3ada914da95485` |

后续每个验收通过的版本均成为下一轮的比较基线，并累积保护更早版本的能力。新建分支、代码合并或构建成功本身不构成新基线验收。

保护对象包括所有已经实现的功能，不限于版本说明中列举的新增功能。每轮须结合实际代码和运行版本补齐受影响清单，不得把文档遗漏解释为允许删除功能。

| 数据与权限 | 原项目、账号权限、保存视角、配置、私有资源及持久化数据；已有接口与文件格式 |

## 2. 每轮开发流程

1. **明确范围。** 列出本轮需求、拟改文件/模块、共享依赖、旧功能影响和验收步骤。先完成方案，再开始实现。
2. **隔离开发。** 从确认的运行基线创建开发分支；使用独立工作目录、测试数据和服务实例，保留备份标签、原构建及用户未提交内容。
3. **增量实现。** 优先新增模块或局部扩展。内部实现可以调整，但对外行为必须满足既有约定；无关重构、依赖升级和入口调整不进入本轮。
4. **保证兼容。** 新字段具有兼容缺省处理；旧项目导入、读取、编辑、保存、刷新和导出结果一致。新增能力不得自动改变旧项目状态。高风险功能应隔离，并在未启用时保持原行为。
5. **检查公共影响。** 涉及坐标转换、模型变换、拾取、事件、状态存储、渲染、资源释放、统一面板或权限时，验证相关调用方及模式切换。关注异步完成、取消、删除、重复进入和异常退出。
6. **验证后交付。** 完成自动检查和相关本机验收，形成实测记录。发现回归先修复或撤回引入问题的改动；不能用新功能完成代替旧功能验收。

## 3. 验证要求

功能代码修改在隔离环境执行已有检查，使用 Node.js 24+ 和依赖锁文件：

```bash
npm ci --no-audit --no-fund
node tools/run-temporary-works-regression.mjs all --output output/compatibility-regression
npm run build
```

全量回归入口收集 `src`、`server`、`tests` 下的 `*.test.ts` 和 `*.test.mjs`，不自动覆盖所有独立专项脚本。应根据影响范围补充专项；模型及 AR 相关的现有入口包括：

```bash
node tests/model-placement-regression.mjs
node tests/model-edit-appearance-browser.mjs
node tools/verify-video-overlay-spatial.mjs
```

浏览器专项须按脚本说明准备 Playwright、Chromium/WebGL 和隔离服务。真实 GPU、编解码、后台转换、项目素材及桌面入口相关行为，还须在本机具备条件的环境验收。涉及 AR 时验证退出后地图、模型、相机、机械、临建和安全功能恢复。

性能检查使用同设备、同素材、同视角和同操作序列，对比基线与候选版本；预先记录相关指标及可接受的测量波动。出现可复现退化须修复后发布，不以提高容忍值掩盖问题。

已有版本说明中的测试数量和通过结果仅为历史证据。本轮必须记录实测结果；跳过、未执行和环境受限均不得记为通过。既有环境条件跳过须核实适用性，新增失败、取消或跳过必须查明原因。相关验收缺失时保持待验证状态，不切换正式运行版本。

纯文档修改核对变更范围、引用路径和内容一致性即可，无需运行应用测试，也不得声称已完成新一轮应用回归。

## 4. 部署与回退

- 发布前核实实际运行进程、目录、提交、构建哈希、地址、端口、数据根和启动包装；依照已有本机部署约束保留 SDK、私有配置、权限及资源路径。
- 不清空 IndexedDB/OPFS，不用旧数据库覆盖当前业务数据。缓存规则如需改变，须保留方案、参数和业务记录，并按需求明确其影响。
- 数据结构变更须事先验证旧数据升级、失败恢复，以及旧代码读取升级后当前数据的兼容性；不能证明兼容时，不采用简单回退代码的方案。
- 回退使用上一可运行代码、构建及匹配启动身份，保留当前业务数据；涉及迁移时使用已验证且保全新增记录的恢复流程。
- GitHub 保存或合并不等于本机部署。未经实际环境验证，不宣布新版本已上线。

## 6. 采样与生成工作量约束

适用于计划中的地表开挖、土体补面和局部压平。用户明确要求避免采样过多导致无法生成；以下为实施与验收条件，尚不代表新功能已经实现。

1. **先估算再执行。** 在发出采样请求、分配大数组或生成网格前，预估范围、边界点、累计高程采样点、输出顶点/三角面、裁剪多边形、拓扑运算量及资源占用；运行中继续检查实际累计值。单项和多任务整体均须有预算，超限提前提示。
2. **设计面不做无效密集采样。** 水平坑底、指定标高压平面、已确定坡面的内部几何由参数直接生成。仅对接边等必要位置有限采样，不能默认遍历整个选区或摄影三角网。设计高程与摄影实测高程必须区分。
3. **自适应细化有界。** 根据边界转折、高差及接边误差细化，设置最小间距、最大细化层数和累计点数上限。禁止默认极小固定间距或最高精度；简化须保留关键转折、保留区及拓扑，在明确误差容限内进行。超出容限时停止并提示调整，不得静默降低精度、截断范围、填掉孔洞或缺块后报告成功。
4. **分块不能绕过总量上限。** 同时控制每批点数、整个任务的累计采样数、分块数量、网格规模、并发请求、重试次数及等待时间。超限可提供缩小范围、按预算分区、减少细碎点、使用已知地面标高等选项。全局任务队列也须限流，不能通过同时建立多个方案绕过预算。
5. **界面保持可响应。** 轮廓处理、三角化及组合计算使用 Worker；依赖 Cesium 场景的高程采样采用有界小批调度，批次间让出界面。无 Worker 时只允许受限小任务；不能把大任务改为主线程同步执行。预览与正式生成分别设预算，界面显示当前阶段与实际进度。
6. **可取消、可超时、无过期写入。** 修改范围、切换项目、关闭效果、取消或超时时停止后续调度并终止可终止的计算。无法立即中止的在途请求，返回后丢弃过期结果并释放临时资源，不能重新写入场景或覆盖新方案。重试必须有界。
7. **复用有效结果。** 相同目标、范围和精度的有效采样可复用；模型变换、数据版本或相关参数改变时正确失效。材质、亮度和显隐切换不得无故重新采样；不在每帧重建。未加载、缺失或非有限高程不得静默按零处理，也不得把新增补面误当成原摄影取样面。
8. **成功后再提交效果。** 完整补面及裁剪参数准备成功后才切换可见状态。采样失败、超时、超限、取消或网格生成失败时，保留原摄影及上一有效方案，不留下先裁剪后补面失败的空洞，不影响其他临建、开挖或压平方案。

预算配置须覆盖采样数、单批数量、并发、细化深度、顶点/三角面、裁剪多边形、拓扑工作量、内存估算、重试及超时。先通过小规模原型和用户本机代表性真实摄影数据确定明确数值及依据，再作为默认值交付；不能直接复制旧模块的限制并声称已验证。

已有 [设计地面说明](temporary-works-upgrade/designed-surfaces.md) 提供了不依赖密集摄影采样的设计面路径，以及 Worker、取消、输出网格和裁剪工作量保护，可参考其处理模式。旧模块的网格/裁剪限制不等于新功能的摄影采样上限；本次约束不得擅自改变旧方案生成语义或重新求解历史数据。

专项验收至少覆盖：普通区域、大面积区域、长而曲折边界、复杂保留区、异常小间距输入、预算临界及超限、多方案并发、采样缺失/失败、取消/超时、连续修改范围、隐藏和删除、重复生成后的资源回收。记录估算与实际点数、输出规模、生成耗时、界面响应、取消响应和失败恢复；预期超限应在预算内明确停止，不能以卡死或长时间无反馈结束。达到预算时可控停止属于正确行为，不得宣称任意规模都能生成。
