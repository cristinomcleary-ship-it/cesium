# 桥梁施工工序三维展示实施方案

## 目标与现有基础

在现有 Cesium 场景中，按“桥梁—墩号/跨号—分项工程—工序”选择施工内容，播放结构形成、机械作业和临时设施搭拆过程。支持计划推演与实际进度展示。演示不写回真实完成记录，不驱动现场机械或传感器。

复用 `src/managementTypes.ts` 中已有 WBS、任务、前置关系、计划时间、资源关联和进度，以及服务端任务依赖校验。新增的是构件映射、工艺模板和播放控制层；施工任务仍由原管理模块维护。

## 构件是第一前提

当前 `tools/sketchup/convert.mjs` 遍历 SketchUp 组件并烘焙变换，`tools/sketchup/glb-writer.mjs` 输出一个 node/mesh，并按材质合并面。已经这样导入的整桥模型，不能可靠自动识别哪些面属于桩基、承台、墩柱或盖梁。

实施时增加可选的“保留组件层级”转换方式，输出 GLB 节点树和构件清单，为每个构件记录稳定 ID、父构件、名称、原组件路径和局部坐标。保持原转换方式可用。

- 原 SKP 已按构件分组：重新导入并检查构件树，批量绑定到墩号与分项。
- 原 SKP 没有分组：先在 SketchUp 中整理组件，或按构件分别导出；不能仅按颜色推断施工构件。
- 已导入的独立构件文件：可直接按资源 ID 绑定，无需等待层级转换。
- 无法分解的整体模型：只能整体显隐/着色，界面明确提示控制粒度。

## 工艺模板

| 分项 | 可配置工序 | 三维对象与机械 |
| --- | --- | --- |
| 桩基 | 桩机进场 → 成孔及桩基施工 → 桩基完成 → 桩机退场 | 逐根桩、桩机；桩序可配置 |
| 承台 | 围护 → 分层开挖 → 垫层及承台施工 → 回填 → 围护拆除 | 围护、土方体、挖机、承台 |
| 墩柱 | 墩柱施工 → 成型 → 相关临时设施拆除 | 墩柱构件及选配设备 |
| 盖梁 | 支架安装 → 盖梁施工 → 拆架 | 满堂支架或少支架，盖梁 |
| 现浇梁 | 支架安装 → 现浇梁施工 → 拆架 | 满堂支架或少支架，梁构件 |
| 预制梁架设 | 设备进场 → 运梁 → 吊装/架设 → 设备退场 | 预制梁、架桥机或汽车吊或履带吊 |

模板生成后允许增删工序、修改时长、并行施工、调整前置关系。是否需要降水、支撑或特殊围护由项目方案配置，不把演示模板当作施工安全方案或工艺审批。

## 数据与播放方式

每条演示绑定引用现有 `taskId`，附加 `componentIds`、机械 `resourceIds`、临时设施 ID、工艺选项和动作轨迹。结构构件记录未施工、施工中、已完成三个显示阶段；支架、围护与机械记录进场、作业、退出区间。临时设施不能和永久结构混为同一完成状态。

播放时按绝对时间计算状态，支持暂停、倍速、拖动、跳至工序、单墩与整桥视图。按时间直接求值，拖回任一时刻均可复现；避免只依赖一次性事件触发导致倒放或跳转漏状态。

共用现有 Viewer，在独立演示会话中暂存并恢复原始位置、材质、显隐、相机及交互状态。机械演示优先使用轻量副本，避免修改现场台账和实时姿态。退出、切项目、删除对象或权限变化时统一释放演示对象。

当前参数化机械包括桩机、挖机和吊机，需补充架桥机、履带吊资产及动作模板；当前临建类型尚不包含满堂支架、少支架和承台围护，需增加参数化组件。架桥机跨度/长度、吊臂参数和吊装路径属于演示配置，不能据此判定实际吊装能力。

## 分阶段落地

1. **构件绑定与单墩示范**：导入构件树、分项分类、现有任务绑定、桩基→承台→墩柱→盖梁的显隐/成型播放、时间轴和退出恢复。以 1# 墩形成可验收完整流程。
2. **工艺与临时设施**：补充围护与分层土方、满堂/少支架模板，机械进退场与基础作业动作；加入现浇/预制分支选择。
3. **梁部与多墩协同**：补充架桥机、履带吊、汽车吊架梁模板，多墩并行与跨间依赖、场景范围裁剪与实例复用。
4. **汇报输出与进度联动**：计划/实际对照、视角编排和视频导出；仅从已确认业务记录读取实际进度。

首期验收重点：每个工序能追溯到任务和构件；同一时间点反复跳转结果一致；临时设施按工艺正确出现/退出；结束演示后原场景、实时监测及机械安全模块恢复；大场景按当前分项加载并复用重复构件。
