# 施工安全巡检大屏：数据接入契约

本文对应 `src/safetyTypes.ts`、`src/safetyData.ts` 与 `src/safetyStore.ts`。大屏在原平台内使用同一个 Cesium Viewer；数据适配层只读取本地资料，不修改 CAD、模型坐标、保存记录或视频配准参数。

## 1. 当前样板及证据边界

2026-10-07 对当前本机资料库进行只读验证，得到：

| 内容 | 当前结果 | 数据性质 |
| --- | --- | --- |
| 项目 CAD | 兴善公路主线中心线.dwg | 真实来源 |
| CAD 编号文字锚点 | 146 个 | 真实文字插入点，尚未复核为桩中心 |
| 墩组 | 19 个，7–25 号 | 由编号前缀推定 |
| 施工区段 | 4 个，每五个墩号一组 | 展示分组，非正式施工区段划分 |
| 盖梁、墩柱、承台 | 每个墩组各一个逻辑节点 | 未绑定模型，不代表实体已定位 |
| 导航节点 | 共 227 个 | 含项目、区段、墩组和构件逻辑节点 |
| 无人机航迹 | 活跃视频对应 3467 个原始有效坐标 | 真实回放资料，不代表在线设备 |
| 告警、任务 | 各 6 条 | 明确标记为演示，绑定已有 CAD 锚点 |
| 营业线位置 | 未提供 | 不生成推测的营业线或限界 |

这些数量是本次本机资料快照，不是接口保证的固定值。例：首条演示事件关联 `13-1 桩位标注`，可追溯到 CAD 记录 `8aee5841-db56-42cc-820d-c6790d423e6e`、实体索引 `2387`。后续替换原图或重复导入可能改变本地记录及实体索引，不能把它们直接作为正式 BIM 构件编号。

模型清晰度、工程定位精度、无人机视频配准精度分别验收。大屏主题、描边、动画、相机定位和媒体跳转成功，均不构成上述精度问题已经解决的证据。

## 2. 接入接口

统一入口为：

```ts
interface SafetyDataAdapter {
  load(signal?: AbortSignal): Promise<SafetyDataset>;
}
```

`SafetyWorkspaceOptions.adapter` 可注入新的实现；省略时使用 `LocalSafetyDataAdapter`。业务接口可以替换这一层，界面、图表与场景继续消费相同数据集和状态。

适配器应完整返回一个数据快照。调用方可中止过期加载；`AbortSignal` 中止必须传播，不能把主动取消当成资料缺失。接口失败应列出 `sourceNotes` / `missingData`，保留可用资料；完全没有工程点位时，可使用明确标记的演示数据。

本地实现只读取：

1. `GET /__library/records`：资料清单与保存的 `view.activeVideoId`。
2. 当前 `visible` CAD 的 `record.files.data.url`：`.cadimport` 中间格式。
3. 活跃 `Drone Video` 记录的 `record.files.source.url`：轨迹 JSON。
4. `record.files.video.url` 和 CAD 原图 URL：作为媒体引用，交由现有播放器和资料访问流程使用。

本地文件地址必须位于 `/__library/files/`，不接受脚本 URL、外部来源、反斜杠或路径穿越。不会使用 CAD、轨迹文件内的任意路径自动抓取外部资源。新远程适配器应自行实施鉴权、允许来源和超时控制，不把访问凭据放进前端数据集。

同源 CAD 根据源名称、实际实体内容和坐标配置去重，优先最新保存的可见记录；同名但几何发生变化的资料保留。隐藏 CAD 不生成新的导航节点。去重只影响大屏的数据快照，原资料库和原图层保持原样。

## 3. 核心字段与唯一关联

完整类型以 `src/safetyTypes.ts` 为准。

| 对象 | 必须明确的字段 | 用途 |
| --- | --- | --- |
| `SafetyDataset` | `version: 1`、`projectId`、`nodes`、`timeExtent`、数据来源说明 | 完整快照及公共时间范围 |
| `SafetyNode` | `id`、`parentId`、`kind`、`position`、`provenance`、`description` | 项目 → 区段 → 墩 → 构件导航 |
| `SafetyAlert` | `id`、`nodeId`、`timestamp`、`severity`、`status` | 事件列表、定位、详情与图表关联 |
| `SafetyTask` | `id`、`nodeId`、`timestamp`、`status` | 巡检列表和任务统计 |
| `SafetyDevice` | `id`、`nodeId`、`track`、`status`、`coordinateNote` | 设备范围、回放航迹、状态说明 |
| `SafetyMedia` | `id`、`kind`、`url`、`relation`、`note` | 图纸、照片、视频和文档关联 |
| `SafetyTrackPoint` | `longitude`、`latitude`、`height`、`time`、`mediaSeconds` | 空间位置与媒体时标对应 |

每个 `id` 在同一数据集中必须唯一。`projectId` 必须指向项目节点，`parentId` 关系应为无环树，告警和任务的 `nodeId` 必须存在。任何 `mediaIds`、设备 `mediaId` 都应引用真实存在的媒体条目。生产接口应使用可跨刷新保留的正式业务编号，而不是坐标字符串、显示名称或数组序号。

本地 CAD 锚点 ID 形如 `cad:<recordId>:<entityIndex>`，并保留 `sourceRecordId`、`sourceEntityIndex`。绘图中的独立 POINT 标记仍由此前 CAD 显示策略隐藏；大屏工程锚点来自符合编号格式的 TEXT，并未重新显示 POINT。

模型需要在 glTF / 3D Tiles 属性中保留唯一构件编号，才能填写 `modelFeatureId` 并建立可验证的拾取绑定。当前数据没有此映射，因此不声称三维构件已绑定。正式接入时还应明确模型记录约束：若同时追溯 CAD 和模型两个来源，应扩展独立的来源映射字段，不能将 CAD 实体索引误用于模型 feature ID。

## 4. 真实、推定与演示

`provenance` 必须取以下值之一：

| 值 | 含义 | 当前实例 |
| --- | --- | --- |
| `real` | 有可追溯的实际输入资料 | CAD 文字插入点、原始 CAD、无人机视频和实测记录航迹 |
| `derived` | 根据实际资料推导，推导方法必须说明 | 墩号分组、分组中心、CAD 包络、未绑定的逻辑构件 |
| `demo` | 为演示交互创建，不代表现场事实 | 告警、整改示例、任务及无数据时的合成样板 |

`real` 说明来源真实，不自动表示测量精度、构件语义或高程基准已经验收。例如，真实的 `13-1` 文字插入点可能偏离标注所指的桩中心，不能据此计算施工限界或代替测量放样。

盖梁、墩柱、承台逻辑节点继承父组中心，并在 `description` 明确“未绑定模型、不是实体定位”。展示区段、发光边界及立体厚度来自 CAD 标注包络，仅用于导航和视觉组织，不是施工红线、征地边界或营业线安全限界。

演示告警不宣称现场存在隐患；演示整改不具备验收效力。关闭 `includeDemo` 后，统计、任务、告警与场景事件使用同一过滤结果。没有真实业务接口时，真实告警数量为零，不能把演示数量换标签后当作实绩。

## 5. 坐标、高程与工程尺寸

场景数据使用 `SafetyPosition`：经纬度为十进制度，`height` 为米。数值必须有限，经度在 `[-180, 180]`、纬度在 `[-90, 90]` 内。

CAD 转换复用现有配置与算法：

- 高斯投影：复用 `createGaussKrugerToWgs84Converter`，保留中央子午线、椭球、轴顺序、带号及是否含带号前缀；Z 仅加现有 `heightOffset`。
- 自定义 CRS：通过现有 `proj4` 转成 WGS84；不额外叠加未知的地图纠偏。
- 本地坐标：复用现有 ENU 锚点、参考点、旋转、缩放和 Z 规则。

本机 CAD 配置为 GRS80、高斯投影中央子午线 `120.7833333°`、`eastNorth`、平面单位米。源图常见 Z 为 0；这一数值不能解释为已经复核的工程绝对标高。源单位、垂直基准、控制点精度仍须正式资料确认。

展示性拉伸、光柱和扫描高度由场景特效管理，不能回写工程模型。两种显示模式共用完全相同的工程坐标、ID 和转换结果。若真实工程需要不同的垂直基准转换，必须提供明确的基准与转换参数，不能通过调高模型来掩盖配准差异。

## 6. 无人机轨迹与时间

当前轨迹输入为：

```json
{
  "source_crs": "EPSG:4326",
  "flight_info": { "timezone": "+08:00" },
  "trajectory_points": [
    {
      "source_timestamp_ms": 1787127616562,
      "video_time_ms": 0,
      "recorded_at": "2026-08-19T16:20:16.562",
      "position": {
        "longitude": 120.890825,
        "latitude": 30.836687,
        "altitude": 99.221,
        "relative_altitude": 70.105
      }
    }
  ]
}
```

时间必须区分两个轴：

- `time`：UTC epoch 毫秒，用于告警、筛选范围和共享历史时间轴。
- `mediaSeconds`：视频内部秒数，来自 `video_time_ms / 1000`。不能以 Unix 时间直接设置 `video.currentTime`，也不能假设轨迹时长等于视频时长。

绝对时间优先 `source_timestamp_ms`。次选带时区的 `recorded_at`，或使用源文件明确的 `flight_info.timezone`。没有时区的文本时间不会按浏览器当前时区猜测。若同一轨迹已有有效的绝对时间与媒体时间锚点，可为缺失绝对时标的样本推导时间，并在 `sourceNotes` 披露数量。

位置高度只取 `position.altitude`，不会用 `relative_altitude` 替换。DJI 字段“absolute”并不充分证明是椭球高或正常高，因此当前仍明确记录“高程基准未知”。媒体和源坐标系不符合此契约时，应由适配器验证或转换，不能把非 WGS84 数值直接当作 WGS84。

有效坐标全部保留，不平滑、不抽稀、不通过动画连线替代实际轨迹。无效行、时间倒退及超过 5 秒的采样缺口创建新的 `segment`。实际轨迹分段绘制；移动光标仅在同一连续段内插值，段外及数据范围外返回无位置。5 秒是本版保守的显示缺口规则，不代表设备采样质量已经验收。

视频可能在轨迹缺测期间仍有画面。视频时间映射与空间插值必须分开：可继续播放已有原片，但不能补造无人机坐标。若 epoch 与媒体时轴不单调、重复或来源不匹配，控制器应停止自动关联并披露问题；不能对非单调数组直接做二分时间映射。

复用原播放器时，还必须确认当前媒体确实属于所选 `mediaId`。重新打开大屏、切换原 AR 视频和刷新资料后均应重新核对。退出大屏回到原 AR 时，应按原播放器的精确 PTS 或原有比例策略同步，不能用一个统一时长比例覆盖其校验过的时间逻辑。

## 7. 统一筛选与指标定义

`SafetyStore` 提供只读入口 `dataset`、`state`、`view`，以及 `subscribe`、`patch`、`select`、`setDataset`、`dispose`。订阅建立时会立即收到当前快照，返回的函数负责取消订阅。

界面、图表和场景使用同一 `SafetyView`：

- 当前节点及其后代限定业务范围；面包屑保留父级，便于逐级返回。
- `timeRange` 为闭区间，对事件和任务使用相同的毫秒时标过滤。
- `severity` 对告警过滤，并限制相关工程分支、任务列表和场景对象。
- `includeDemo` 同时控制演示节点、事件、任务、设备和媒体。
- 设备可关联当前节点的祖先项目，表示项目级设备，不表示设备已经进入当前构件取景范围。
- `time` 是回放光标；更改光标不等于更改统计窗口，统计范围由 `timeRange` 决定。

| 指标 | 单位与含义 | 不代表 |
| --- | --- | --- |
| `metrics.points` | 个；筛选范围内 `componentType: pile` 的标注/逻辑作业点 | 已复核实体桩基总数 |
| `metrics.alerts` / `high` | 条；筛选事件与其中高风险事件 | 未接入接口时的真实现场隐患实绩 |
| `metrics.tasks` / `completed` | 项；筛选任务与完成任务 | 实测巡检覆盖率或正式验收进度 |
| `metrics.demoAlerts` | 条；当前事件中的演示记录 | 真实告警 |
| 热力分布 | 条；筛选告警按位置汇聚的事件数量 | 风险概率、安全距离或单位面积测量值 |

热力色斑是相对邻域分布，随筛选窗口重新归一化。透明度只调整视觉展示，不改变数据权重。图例应保留指标名称、单位、时间范围和演示标识。

## 8. 媒体关系

`relation: "project"` 表示项目参考资料；`relation: "object"` 才表示已验证的对象关联。当前 CAD 原图与无人机视频均为项目级引用。

点击 CAD 锚点后能展示项目无人机视频，不意味着该帧包含该墩位，也不意味着视频已经准确配准。对象专属照片、视频取景匹配、图纸页码与构件资料索引接入后，应保留验证来源、拍摄时间和正式构件 ID，再建立 `object` 关系。

设备在线状态也必须来自真实状态接口。当前历史无人机记录使用 `status: "replay"`，不会标为在线。

## 9. 生产接入缺项

1. 营业线实测中心线、线路名称、里程、坐标系和正式限界数据。
2. 经批准的施工区段边界、正式墩号与编号对照。
3. 保留唯一构件编号的模型，以及 CAD、模型 feature ID、业务台账之间的映射。
4. 正式设备清单、在线状态、告警、巡检任务、整改记录和验收接口。
5. 实测控制点、CAD 源单位、水平坐标基准、垂直基准及转换精度资料。
6. 构件照片、对象专属视频、拍摄时标、图纸及资料索引。
7. 独立的模型清晰度验收数据和视频配准检查点；二者不由大屏视觉效果代替。

## 10. 数据层验证

运行：

```powershell
node --experimental-transform-types --test src/safetyData.test.ts
```

当前数据层 18 项测试覆盖：现有坐标转换一致性、来源不变、真实与推定区分、同源去重、隐藏/非法 CAD 排除、安全 URL、两个时间轴、未知时区拒绝、航迹断段、无外推、统一筛选、订阅释放、时间范围钳制、活跃视频选择、浏览器 fetch 接收者、失败降级和中止行为。

浏览器交互、原生视频解码、退出后 AR 时间恢复以及反复打开/关闭的资源表现由大屏集成验证另行记录；数据层测试通过不能替代这些验证。
