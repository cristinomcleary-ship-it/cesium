# 第一轮技术设计：构件管理与独立遮挡

状态：**审查后设计，依据用户再次提供的完整任务消息执行；不是已实现或已验收功能。**

## 1. 范围与不变量

使用用户指定分支，保留参考基线追溯与当前运行版本的已验收能力。第一步仅接 A001# 和 TN021，真实样板通过后再开放全线。

结构零变更约束：

- 原 GLB、SKP、DAE、台账、原始网页原位只读，不重新建模、简化、焊接、补面、重采样或改变三角面。
- 节点原始矩阵、单位、坐标轴、实例、材质及 componentId 保留；新增状态置于独立 sidecar，不写回源包。
- 任何运行时渲染分组必须可逐节点、逐 primitive 追溯至原 GLB，未经同等几何核验不得启用。
- 本轮不编辑视频 AR 源码、协议、缓存签名、视频方案或后端。既有场景接管边界内暂停并恢复本轮效果。
- 原资料库与既有场景分组保持其含义；新增功能未启用时，旧资源走原路径。

## 2. 数据与状态层

### 2.1 只读资产描述

读取完整组件台账、结构库索引及选定 GLB，验证 schema、包版本、SHA256、重复/缺失 ID、树环、未知父级、节点名字唯一性和节点/mesh/extras 对应。先校验，再把资源一次性接入场景；失败不留下半个模型。

实体引用为 `{assetFingerprint, instanceId, componentId}`。componentId 在同一交付包内唯一，但同一包可以有多个场景实例，不能使用单个全局 ID 覆盖不同实例。

建立三种明确索引：

- `componentId → nodes/primitives` 与反向 `runtime model + node index → componentId`。
- `groupId → descendant componentIds`，来源是分类树，不复制实体。
- `unitId → componentIds`，来源是单元清单，包含跨分类附属成员；支承关系仅作关系展示。

全线实例与样板实例互斥显示/加载同一范围，或通过显式替换事务去重。独立 108 包不是全线覆盖全集，最终覆盖以完整 GLB 的 25,258 实体为准。

### 2.2 状态分离

候选状态有 `visible`、`occlusionEnabled`、选中 ID、树展开状态。显示和遮挡两个布尔量互不改写。旧资源没有 sidecar 时继续原行为；新包初值继承源台账（已核实为可见、独立遮挡关闭）。

权限/项目激活与用户显示是不同门控。退出项目、撤销权限或卸载资源时，颜色和独立深度都必须移除；不能以“隐藏仍遮挡”为由让无权限资源继续渲染或可拾取。

侧挂状态按项目、账号、实例、包指纹隔离。持久化采用新文件/记录、原子保存及严格校验，需根据现有资料库接口确定最终落点；不得把构件规则塞进旧视频方案。旧版本忽略新 sidecar，不删除它、不覆盖原记录。

### 2.3 三级控制范围

按用户任务消息的单构件、分组、全选，落实为“全工程/分组或单元/单构件”。组和全选通过统一命令写叶子状态，并以 true/false/mixed 回显，不新增互相冲突的父级覆盖优先级。

三级分别验证两套开关的实际颜色与深度效果，不以三个树层级的外观冒充功能。

## 3. 构件树、双向选择与显隐

使用独立可虚拟滚动的构件树，按需展开和搜索；复用原面板容器，避免重绘整个工作台。沿用场景显示的资源入口，子构件不加入其 5000 项 store。

树选中只更新选择和高亮，不隐式移动镜头；明确“定位”才移动镜头。三维点击通过原 Model 的 node/primitive 映射选中，展开所属分类，显示单元归属。几何重叠、多个实例、参考几何和未绑定对象均有确定处理。隐藏实体可以在树中选中，但普通点击不得命中隐形深度对象。

高亮不写源材质、不改变业务显隐/遮挡，不改变模型矩阵。样板先验证对单节点的运行时材质覆盖或隔离高亮 pass；如果只能整模型着色，不得作为构件高亮交付。

点击模式与整模型位置编辑、开挖/剖切绘制、标注、机械操作互斥。在明确构件选择模式处理事件，不安装常驻抢占所有左键的 handler。退出、Esc、失败、权限变更和卸载均释放 handler、还原相机控制。

## 4. 独立遮挡设计

### 4.1 首先冻结“遮挡源 → 受挡目标”

依据离线页，新增独立工程深度供明确的受挡绘制阶段使用。样板先证明同一世界相机下实际受挡几何的深度结果，并检验普通地理场景、地下查看和剖切兼容；工程遮挡不自动改变摄影/便道/临建的显隐或裁剪业务规则。视频 AR 明确保持本轮保护边界。

受挡目标与独立深度的作用范围须在界面和测试中可观察，不能隐式改变整个场景，也不能把仅测试面通过当作既有场景兼容全部通过。

### 4.2 颜色与独立深度真值表

下表描述独立遮挡语义，不取消正常表面的自身深度测试。

| visible | occlusionEnabled | 颜色 pass | 专用遮挡深度 pass |
| --- | --- | --- | --- |
| true | false | 正常颜色、材质和自身表面深度 | 不提交该构件 |
| true | true | 正常颜色、材质和自身表面深度 | 提交该构件 |
| false | false | 不提交 | 不提交 |
| false | true | 不提交 | 仅提交深度，普通拾取排除 |

剖切后的遮挡几何必须与明确的切面语义一致；若显示已剖开但遮挡仍用未切开的实体，将导致查看内部时出现虚假遮挡。不得擅自设定“隐藏=卸载”，也不得让一个组的开关改变别组或旧摄影开关。

### 4.3 推荐验证方向：独立深度目标与显式合成

对工程构件建立隔离的遮挡 pass，使用原节点几何、实例变换、相机和必要裁剪，写入专用深度纹理/帧缓冲；颜色写关闭。受挡目标在自己的颜色 pass 或合成步骤读取该深度。普通主场景 pickPosition/采样不使用隐形构件深度。

这是降低全局副作用的设计方向，**尚未经 Cesium GPU 原型证明**。Cesium 高层 Model API 没有现成的节点级任意 pass 控制开关；需集中、受标记、版本锁定的命令适配器，并验证多视锥、log-depth、近远裁面、缩放、设备像素比、透明/MASK 材质、背面及上下文恢复。

适配只处理本轮明确登记的工程实例，未标记 Model、Tileset、CAD、临建完全绕过。不能修改引擎全局原型或在每帧遍历/改写所有场景命令。材质 alpha MASK 的孔洞不可被深度代理填满。全线不得为每个实体复制 Model/纹理，状态更新应按改动批次处理。

### 4.4 备选方案与淘汰条件

| 方案 | 可能适用范围 | 必须解决的问题 |
| --- | --- | --- |
| 原节点派生 depth-only 命令 | 仅在能够确保预深度顺序且目标已定义时 | 不能晚于受挡颜色；覆盖多视锥、透明、反向加载和裁剪；不得污染全局拾取 |
| 专用构件 Primitive/批次 | 原 Model 无法提供可靠命令控制时 | 不改变输入几何；严格节点/primitive溯源；保留纹理/alpha语义；附加内存与速度测量 |
| 工程目标专用合成层 | 遮挡仅对工程目标生效时 | 与现有摄影深度、抗锯齿、透明目标相容；不重新定义外部资源显隐 |

下列路径直接淘汰：alpha=0 冒充深度、show=false 后声称仍遮挡、后绘深度冒充全场景正确遮挡、扩大裁剪范围代替准确深度、重建近似包围盒代替原实体、改视频 AR 来绕过地图实现。

若主方案遇到内部引擎限制，交付真实失败画面、命令顺序和原因，比较备选方案后继续；不得把未覆盖的模式标为通过。

## 5. 既有功能兼容

便道/临建/硬化的摄影裁剪仍由现有 TemporaryWorksClippingManager 负责；本轮不夺取 tileset.clippingPolygons、clippingPlanes 或 terrain 集合。新深度几何仅借用经过验证的当前切面语义，不销毁外部所有者的集合。

新增控制器通过运行版本已有 SceneEffectsCoordinator 注册。在 AR 或其他既有场景接管开始时暂停本轮独立效果，释放时按当前用户意图恢复，避免旧快照覆盖新状态；视频模块保持原字节。正常模型继续沿用原有融合行为，本轮不声称构件规则进入视频融合。

隐藏/删除/项目切换/撤销权限/加载迟到/纹理失败/上下文丢失均走统一撤销事务。取消后禁止晚到异步任务重新挂载。既有模型外观和位置编辑对同一实例矩阵有明确订阅，禁止深度代理停留在旧位置。
