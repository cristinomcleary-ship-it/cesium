本次需求是裁除与工程实体冲突的倾斜摄影。此前橙色检测面使用独立深度，只能证明检测面的遮挡，不能证明摄影像素已被裁除。修复后，构件的 O 状态通过共享裁剪管理器贡献真实摄影轮廓；V 只决定工程模型可见性。单构件、分组、当前范围全选共用同一状态，V=false/O=true 仍裁剪摄影。关闭总开关或解除接入只撤销工程自身贡献，保留便道、临建等其他贡献。

## 几何与精度

模型仍原位只读。解析原 GLB 的 POSITION、indices 和节点变换，核对运行时节点链，并组合实际实例定位、轴修正和比例；不重写顶点、材质、节点、源文件或实例矩阵。A001 包含 6 个实体、1,016 个原始三角面；TN021 包含 199 个实体、7,388 个原始三角面，其中轨道构件纳入对应实体集合；全线包含 25,258 个实体、805,322 个原始三角面。遍历计数包括投影后退化的侧面，不能据投影面积删去源面计数。

Worker 对真实三角面的地心投影求并集，保留凹角、分离区域和孔洞。没有用包围框、凸包或包围球替代轮廓。固定 1e-8 米整数格网只用于投影布尔运算；不改变 GLB，不在失败后放宽精度。含孔洞或大环在 Worker 中剖分并校验面积守恒。包内运行资源哈希及计算前后原文件哈希均核验；完整 GLB 的 SHA-256 为 `0a767961b6ba11845ef1fd7c8e4932ee3e8c57d771f967d2736cca94d4f70eac`。

原生裁剪把绝对球面角度存入 Float32，真实 1 米圆桩的多个边界顶点会合并，造成区域消失。工程贡献活动时改用局部 ENU 米坐标、中心投影与逐边点内判定，BVH 包围框仅用于排除查询。GPU 浮点精度与 Worker 的 1e-8 米格网是两项不同指标；没有通过扩大圆桩、提高 SDF 分辨率或放宽边界断言补偿。原调用的面积阈值保持不变，工程 scope 单独允许非零小面。

真实 A001 小桩验收同时读取摄影像素和同一像素的 1×1 拾取结果。深桩的地心投影不是理想水平圆：独立 CPU 原三角面核验中，旧 ±0.45 米下方角点位于实际投影内约 0.65 毫米；选取仍在 1 米包围框内的 ±0.49 米四角后，四点均严格处于实际轮廓外，最小间距 53.45 毫米，内部五点最小间距 189.03 毫米。测试据真实投影设置采样点，不把邻域拾取跨越边界误报为裁剪失效。

## GPU 障碍与处理

初版精确着色器在本机 ANGLE / D3D11 上出现 `Error compiling dynamic pixel executable`，同时产生 `GL_INVALID_OPERATION`。仅 CPU 编译检查和纹理数值正确不足以证明 GPU 可用，因此该版本未计为通过。

诊断定位到动态像素着色器编译路径。最终形式使用显式高精度纹理采样器，以实际 BVH 节点数量为上限遍历，以每个原环的真实顶点数遍历边；点内判断返回布尔值，最后在主阶段执行 discard。上限覆盖完整输入，不截断节点、边或构件。最终样板与全线共 27 项在 RTX 4080 的真实 D3D11 渲染器上通过，浏览器错误、GPU 警告及请求失败均为 0；测试前后 11 个相关源文件的哈希一致。
