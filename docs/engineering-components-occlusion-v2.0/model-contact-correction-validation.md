## 实际行为与保护范围

工程模型列表每行的操作顺序为“定位、调整位置、外观、模型遮挡”。接入依据是已经成功加载的 Cesium `Model`，不按文件扩展名限制；已转换的 SKP 模型和 GLB 使用同一服务。这不证明尚未配置的格式转换器可用，也不替代原格式导入验收。

模型显示 V 与遮挡 O 独立，隐藏模型仍可操作遮挡按钮。模型行总开关与构件面板共用同一份贡献；Jiashan 单构件、分组、全选三级 O 决定贡献中的实体范围，69 个参考对象不作为实体。关闭或切换构件树不清除其他模型的贡献，也不把既有构件选择改回整模型。开关、目标和构件选择按项目、账号、实例及实际资源哈希隔离保存。

摄影仅在进入原闭合实体内部或接触原三角面时裁除。高架下方、不同楼层之间、模型上方和隧道空腔继续显示；模型有多份时按贡献并集处理。开口、非流形、自交或其他无法证明内部的几何只使用原表面接触，界面明确显示“表面”或“实体与表面混合”。不自动封口、补厚度、移动模型或以贯穿高度的投影代替三维实体。包围盒只用于候选排除，最终判断使用原三角面。

读取、拓扑和 GPU 数据准备均基于原运行时顶点、索引、节点和实例变换。没有重写源 GLB、SKP、模型结构、材质或摄影数据，没有修改数据库结构。只读差异审查确认视频 AR 模块源文件未变；既有便道、临建和地表的二维裁剪仍走原独立逻辑。

## 发现并修复的边界

- **远距离斜视精度：** 首次真实 GPU 回归发现共面摄影在相机距离 1000 米、斜视 45° 时漏裁。原因是 GPU 视空间位置再转回工程局部空间时发生单精度抵消。修复使用实际摄影 `v_positionMC`，由 CPU 双精度组合摄影到工程局部矩阵；legacy 实例分支遵循固定 SDK 的专用变换顺序。共面摄影现在裁除，原面上下各 0.01 米的摄影保留；没有扩大固定接触阈值。完整说明见 [三维接触位置的计算精度](model-contact-position-precision.md)。
- **权限与释放：** 普通更新失败保留仍有效的已提交结果；删除、关闭或撤权必须撤掉该所有者。若释放时其他贡献的 GPU 重建失败，卸载受影响的自有集合，将其余期望状态标为未生效，等待有界重试，不保留失权贡献或逐帧重复分配。外部所有者和其他摄影目标不被清除。
- **三维模式：** 工作台确实提供场景模式切换。非稳定三维模式（2D、Columbus、morph 或尚未达到 `morphTime=1`）取消计算并撤销本服务的贡献，保留已保存开关和已完成几何。回到稳定三维后按当前模型位置恢复；异步旧结果不能迟到挂回。生命周期 CPU 和最终生产浏览器均通过；浏览器实际执行 2D/Columbus 过渡后返回三维，验证裁剪暂停、几何缓存复用和真实像素恢复，无新增 Worker。
- **原生复选框点击：** 真实主工作台发现全局输入框焦点样式使复选框在按下时从约 13 像素变成 37×35 像素，导致抬起落点离开原控件。工程构件面板局部固定原生复选框为 16×16 像素，保留键盘焦点提示。最终生产包的真实鼠标点击及按下/松开前后坐标、尺寸、目标和节点连接状态断言通过，未使用强制点击或修改状态来绕过控件。

## 性能与预算

全线实测读取约 7.70 秒，Worker 往返约 11.22 秒，其中几何算法约 10.58 秒。三次各 30 帧窗口的关闭耗时为 184.7、185.9、179.5 毫秒，开启耗时为 183.1、184.8、184.9 毫秒；应用加 6 帧耗时为 85.8、70.9、64.2 毫秒。这是合成摄影验收场景中的墙钟测量，包含帧调度，不是 GPU 独占计时或任意生产场景的帧率保证。

读取预算为每次 300 万三角面、512 MiB 输入和 120 秒；几何阶段保留完整输入，具有 5000 万次拓扑检查预算。多模型计算共享一个活动任务及最多八个等待任务的队列；等待取消不读取网格，活动任务真正停止后才释放名额。输入快照、拓扑与输出可同时驻留，512 MiB 不能表述为进程总峰值内存限制。

GPU 合并上限为 32 份完整模型贡献、600 万三角面，并核验设备纹理容量和浮点整数索引范围。超时、超限和不支持的顶点动态变换明确报错，不降精度、跳过失败实体或将部分结果标为完整。已验证的公开模型整体位置编辑可复用局部几何；任意第三方直接修改单个节点矩阵不属于本次实时形变支持承诺。
