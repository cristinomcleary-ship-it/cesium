# 三维接触位置的计算精度

工程接触裁剪必须判断摄影片元是否位于原模型实体内，或与原表面接触。它不采用贯穿高度的投影，也不通过增加固定厚度维持视觉效果。

## 远距离斜视中的误差来源

初始三维实现使用摄影片元的 `v_positionEC`，再用工程局部坐标至视空间的逆变换求接触点。Cesium 在顶点阶段已将模型坐标乘以模型视图矩阵，并以 GPU 单精度插值这个视空间位置。相机距目标较远时，逆变换需要抵消较大的平移数值；转回局部空间无法找回前一次单精度运算丢失的有效位。

实际 RTX GPU 验收发现：原表面与合成摄影完全共面，近距离正视可裁剪，但相机距离 1000 米、斜视 45° 时漏判。几何数据的打包误差界不能覆盖这次相机空间转换引入的误差。这是坐标计算路径缺陷，不能把扩大固定接触阈值作为修复。

## 修正后的计算路径

固定版本 Cesium 1.144.0 的 `GeometryStageVS` 已输出 `v_positionMC`。它对应解码、实例和顶点处理后的模型坐标。新接触阶段直接使用该坐标，而不经 `v_positionEC` 或单精度地心坐标中转。

设：

- `E` 为工程局部坐标到世界坐标的矩阵，含工程几何中心重定位；
- `P` 为当次摄影 draw command 的模型矩阵；
- `pMC` 为摄影片元的模型坐标。

CPU 使用双精度先计算 `L = inverse(E) × P`，GPU 只计算 `pLocal = L × pMC`。大地心平移在 CPU 上抵消，相机位置不进入 `L`。相机远近、朝向和视图变换因此不会给接触位置额外引入一次“大数相减”。摄影或工程模型移动后，矩阵在对应 draw 的 uniform 求值时更新。

普通 glTF 与 `EXT_mesh_gpu_instancing` 使用 `UniformState.model`。固定 SDK 的 legacy i3dm 流程已将 `instance × axis × node` 乘入 `positionMC`，所以该分支使用 `model.modelMatrix × sceneGraph.components.transform`，避免重复应用轴向、节点和实例变换。它与 SDK `LegacyInstancingStageVS` 的位置计算顺序一致。

本次修复不修改原三角面、BVH、闭合体/空腔判断或既有数值接触误差界。便道、临建的二维裁剪继续使用原独立谓词。

## 验收约束

CPU 回归检查实际 draw 模型矩阵的使用、工程局部中心抵消、摄影变换更新、相机矩阵变化不影响几何矩阵，以及 legacy 实例专用矩阵顺序。GPU 回归必须同时覆盖近距离与 1000 米斜视：共面摄影应裁剪；上下各偏离原面 0.01 米的摄影应保留，且使用真实像素、原生拾取与 WebGL 错误检查。只有真实运行报告可以证明该项验收通过。

## 2026-11-21 实际验证记录
