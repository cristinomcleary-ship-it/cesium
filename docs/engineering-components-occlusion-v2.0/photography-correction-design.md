# 工程构件摄影遮挡：需求纠正与修复设计

用户明确：模型与倾斜摄影冲突的区域，遮挡对应倾斜摄影，沿用临建的逻辑。上一轮 `97f3a909a8cbe144dd75d481e2ef47d77a73e281` 只有独立橙色检测面消费构件深度，没有向摄影裁剪管理器注册任何工程范围，因此不能视为该需求已完成。之前 GPU 检测面测试仍是有效的诊断测试，但不能作为摄影遮挡验收。

本文件在修复产品代码之前编写。修复在独立候选目录进行；当前正式入口、原业务数据和源模型包保持原位。

## 技术方案

1. 为已绑定工程实例选择关联倾斜摄影；界面单独显示摄影遮挡的准备、应用、暂停、失败状态。原“参与遮挡”叶子状态成为摄影遮挡输入，单构件、分组、当前范围全选均使用同一状态。
2. 从已经核验的原 GLB POSITION 与 indices 读取真实三角面，使用 Cesium 的轴向修正、节点变换、实例定位和比例转换到世界坐标。不得使用包围盒、包围球或凸包代替模型轮廓，不改写 GLB。
3. 在 Worker 中计算三角面的地理投影并求并集，保留凹角、分离区域和孔洞。重叠构件合并，避免逐构件建立数万个摄影裁剪对象。预算、时间、取消与版本失效均显式处理；先完整准备，再原子替换已有范围。性能和容量必须用全线实测确定，不能以临建默认小范围上限截断全线。
4. 复用 `getTemporaryWorksClippingManager(viewer).createScope(...)`，每个关联摄影目标注册合并后的工程贡献。工程只管理自己的 scope；便道、临建、地表编辑的贡献与其共同进入同一原生裁剪集合。不得直接替换其他模块的 clippingPolygons、customShader 或 clippingPlanes。
5. 遮挡由 O 决定，显示由 V 决定。V=false/O=true 仍保持摄影裁剪；整个工程实例隐藏也不等于关闭其遮挡。删除、解除接入、撤销权限或切换项目才撤销对应工程贡献。关闭面板不撤销已启用摄影遮挡。
6. 模型位置、角度或比例变化后重算真实轮廓；等待和失败不得应用过期结果。摄影自身矩阵不重复作用于世界轮廓。继承共享管理器已有 AR 暂停及开挖／剖切目标租约，退出时恢复最新状态。视频 AR 源码不修改。
7. 原检测面保留为可选诊断工具；摄影遮挡不依赖它是否开启。关联目标与总开关按已有项目、账号、模型实例、资产指纹隔离保存，不改生产数据库结构。

## 必须通过的真实验收

先 A001#、TN021，再全线。使用原工程 GLB 和真实 Cesium 3D Tiles 摄影测试面，检查摄影像素及几何采样确实消失／恢复；轮廓外和模型凹角的摄影必须保持。测试 V/O 四态、三级操作、关闭面板、整模型隐藏、移动旋转缩放、刷新、删除、权限变化、取消与迟到结果。工程、便道、临建同时存在时关闭工程只恢复工程自身区域；验证开挖／剖切、AR 暂停恢复及原摄影矩阵不变。

实际结果和完整发布 SHA 在实现后另行记录；本设计文档不宣称修复已经完成或部署。

## 实包计算后补充的实现边界

原浮点并集在全线共线三角面上发生 sweep-line 数值错误；工程 Worker 改用固定版本 `clipper-lib 6.4.2` 的整数裁剪。固定格网为 1e-8 米，只作用于摄影投影运算，源 GLB 不改写；记录实际量化误差，禁止失败后逐级降低精度。使用地心射线到实例切平面的中心投影，与 Cesium 摄影裁剪角度一致。含孔洞或大轮廓在 Worker 中精确三角剖分，并核对面积守恒，避免主线程对大环作二次方检查。

实测发现原临建编译器把小于 1e-4 平方米的合法投影三角面视为退化。为完整保留这些面，计划在共享 `temporaryWorksClipping.ts` 增加 **仅按 scope 显式配置的最小面积**；默认和所有原调用保持 1e-4，工程 scope 仅拒绝零面积及无效面积，不舍弃小面。原经纬度、重复点、自交、孔洞、预算和外部所有权保护全部保留。该变更影响编译器与 scope 创建接口，必须新增阈值隔离测试，并重跑原临建、便道、地表编辑和暂停恢复测试。它不改变任何既有临建或便道的参数、判断与结果。

依赖许可证依据：[Clipper 原仓库](https://github.com/junmer/clipper-lib)；其 Boost Software License 1.0 和内置 JSBN 通知随依赖保留。依赖变更仅新增这个精确版本，既有 polygon-clipping 和其他版本均不变。

## 米级构件 GPU 精度修正（实现前设计）

真实 A001 圆桩 GPU 验收发现：原生 ClippingPolygonCollection 将绝对球面角度存为 Float32，1 米直径轮廓可量化到零宽；在未改动的 97f 基线上，同位置 2 米临建轮廓也复现。这阻止单构件验收，不以扩大轮廓或跳过小桩解决。

增加工程 scope 显式启用的局部坐标解析裁剪。共享管理器仍唯一拥有集合；存在活动工程贡献时，把所有活动贡献的原轮廓转换到局部 ENU 中心投影，构建有界 BVH。GPU 从相机坐标计算局部投影，查询 BVH 后用原边逐边判定点是否在轮廓内；包围框只用于加速排除，不作为裁剪形状。无工程贡献时，原有默认路径保持原样。保留孔洞剖分和所有原顶点，不使用 SDF 分辨率或扩大区域补偿。GPU Float32 局部米坐标精度与 CPU 的 1e-8 米计算格网不同，验收不得混称。

新增 preciseGeometry.ts、preciseClipping.ts 及对应测试；共享 temporaryWorksClipping.ts 仅增加 scope 选择集合实现，现有 cesiumOwnedClippingShader.ts 在精确版本 SHA 守卫内增加自有集合的显式分支。其他集合、反向裁剪、默认临建路径保留原有着色器。必须验证真实 1 米圆桩、凹角、共存、暂停恢复、全线容量、相机移动及旧模块 GPU 回归。
