# 现场人员定位器接入

平台已提供通用 HTTP 位置上报接口、受权限控制的读取接口及页面轮询。真实设备仍须由厂商或现场集成方提供协议适配器；本轮未连接现场硬件，未验证任何品牌的定位精度。

## 接入流程

设备 / 定位基站 → 厂商平台或现场网关 → 数据转换适配器 → 平台 HTTP 上报接口 → 已保存的人员工作区域判定 → 页面提示。

| 现场已有设备输出 | 适配器需要完成的工作 |
| --- | --- |
| GNSS / RTK 经纬度 | 确认坐标基准、经纬度顺序、采集时间、水平误差口径、高程基准，生成统一样本。 |
| UWB 本地 X / Y / Z | 用现场控制点完成坐标标定，将本地坐标转换成平台使用的 WGS84；核对坐标轴方向、单位和高程，不能把 X / Y 当经纬度。 |
| 厂商云平台 HTTP / MQTT / WebSocket | 适配器在服务器或现场网关订阅 / 读取厂家消息，核验厂家凭据，转换为本页定义的 HTTP 请求。平台不内置这些厂商协议客户端。 |
| 只有串口 / 蓝牙输出 | 现场网关先采集设备数据，再完成上述转换和上报；网页无需持有设备口令。 |

确定具体适配器前，请向设备供应商索取：**品牌型号、协议 / SDK 文档、一条原始报文、设备唯一编号、坐标系与高程基准、时间单位与时区、精度字段定义、网络接入方式**。只知道设备名称不能完成联调。

## 1. 在页面保存人员绑定

1. 进入防护人员编辑，绘制独立的“人员工作区域”，不是防护责任区。
2. 填写定位设备编号，例如 `tracker-01`，设置定位失效时间，保存配置。
3. 从管理员已授权的 `GET /__management/state?projectId=…` 响应中找到对应 `collections.railSafety` 记录，取得其 `id` 作为 `guardId`。`projectId`、`guardId` 和 `deviceId` 必须与已保存记录完全一致；设备编号区分大小写。

一项目内只允许一个有效人员绑定同一设备。更换人员后，服务端凭据也要重新绑定并重启；旧人员凭据不能向新人员上报。

## 2. 配置服务端专用凭据

复制本目录 `positioning-devices.template.json` 到项目目录之外的服务器私有目录，例如 `C:\ProgramData\CesiumPrivate\positioning-devices.private.json`。**不要放进项目根目录、项目资料目录、public、src、dist 或浏览器存储，也不要提交真实配置到 Git。** 开发服务器可能将项目中的 JSON 作为静态文件提供，因此凭据必须放在其服务目录之外。该配置只由服务器启动时读取，不通过页面下发。

每台设备使用独立随机密钥。下列命令在本机生成一个私有文件，文件中包含适配器使用的原始 token 和平台配置使用的 SHA-256 哈希；命令不会在终端打印 token：

```powershell
New-Item -ItemType Directory -Force 'C:\ProgramData\CesiumPrivate' | Out-Null
$env:CESIUM_CREDENTIAL_FILE = 'C:\ProgramData\CesiumPrivate\tracker-credentials.private.json'
node -e "const c=require('node:crypto'),f=require('node:fs');const token=c.randomBytes(32).toString('base64url');f.writeFileSync(process.env.CESIUM_CREDENTIAL_FILE,JSON.stringify({token,tokenSha256:c.createHash('sha256').update(token).digest('hex')},null,2),{flag:'wx',mode:0o600})"
```

把 `tokenSha256` 填入私有设备配置，将 `enabled` 改为 `true`，填写准确的项目、人员及设备 ID。原始 `token` 仅交给该设备的服务器适配器或现场网关；不要使用管理页面登录 cookie 代替。Windows 上还应给私有文件设置仅服务账号可读的访问权限。

启动平台前，设置环境变量：

```powershell
$env:CESIUM_POSITIONING_CONFIG_FILE = 'C:\ProgramData\CesiumPrivate\positioning-devices.private.json'
npm run dev
```

路径替换为实际绝对路径；使用现有部署服务时，把环境变量加入原服务启动配置并重启。没有设置此变量时，上报接口关闭；文件损坏、重复绑定、重复密钥哈希或未知字段会导致启动失败，不能默默以空配置运行。修改配置或撤销凭据后要重启服务。重启清空内存定位样本，需等待设备新上报。

这里使用服务端静态设备凭据的 Bearer 认证，不是完整 OAuth 授权服务。现场网络传输应通过 HTTPS 或受保护的本地网关，TLS 在反向代理终止时应限制后端监听与访问；不要把开发服务器直接暴露到公网。Bearer 凭据的传输方式与保密要求见 [RFC 6750 §2.1、§5.3](https://www.rfc-editor.org/rfc/rfc6750.html)。

## 3. 适配器上报统一样本

**POST `/__management/positioning/ingest`**

请求头：`Content-Type: application/json`、`Authorization: Bearer <该设备 token>`。请求正文须严格包含下表字段，不接受其他字段；`position-sample.template.json` 中的 null / 占位文字必须替换成设备真实数据，模板本身不能直接上报。

| 字段 | 约定 |
| --- | --- |
| `projectId` | 服务端凭据绑定的项目编号。 |
| `deviceId` | 服务端凭据及人员工作区绑定的设备编号。 |
| `coordinateSystem` | 固定 `WGS84`，坐标转换由适配器完成。 |
| `position.longitude` / `latitude` | 经度 / 纬度，十进制度。 |
| `position.height` | WGS84 椭球高，米。设备输出的海拔 / 本地高程须先转换；不能无依据填写 0。 |
| `timestamp` | 设备采集时刻，带时区的 ISO 8601，例如 `2026-10-14T14:00:00+08:00`；不是服务器转发时刻。 |
| `accuracyMeters` | 水平定位不确定半径，米；由设备精度或经核验的适配器转换提供，不能把 HDOP 数值直接当米。 |
| `source` | 此网络接口固定接收 `measured`；模拟只能用页面独立演示入口。 |

Cesium 的经纬度转地心坐标接口将高度解释为椭球以上的米数，见 [Cartesian3.fromDegrees 官方说明](https://cesium.com/learn/cesiumjs/ref-doc/Cartesian3.html#fromDegrees)。平台当前只按水平工作区判断，不能据此区分不同楼层。

适配器把一条**实际设备采集样本**写入 `measured-position.json` 后，可从受控终端验证请求：

```powershell
curl.exe --request POST "$env:CESIUM_PLATFORM_URL/__management/positioning/ingest" --header "Content-Type: application/json" --header "Authorization: Bearer $env:CESIUM_TRACKER_TOKEN" --data-binary "@measured-position.json"
```

`CESIUM_PLATFORM_URL` 是实际平台 HTTPS 地址；`CESIUM_TRACKER_TOKEN` 从适配器私有凭据注入环境。不要将密钥放到 URL、前端脚本或普通日志中。上报频率由现场数据频率及容量确定；页面默认每 2 秒读取一次。

成功返回 HTTP `202`，包含 `accepted`、项目 / 设备编号、采集时刻及 `receivedAt`。成功只表示已接收合法数据，不意味着人员位于区内。

| 返回码 | 处理方式 |
| --- | --- |
| `401 DEVICE_AUTH_REQUIRED` | 核对该设备 token；管理 cookie 不授权设备上报。 |
| `403 DEVICE_SCOPE_MISMATCH` / `DEVICE_BINDING_INVALID` | 核对三项绑定和实测来源；禁止自动重绑定人员。 |
| `409 POSITIONING_TIME_CONFLICT` | 重复、乱序或比服务器超前 5 秒以上；校时后发送新的真实采集点。 |
| `422 POSITIONING_STALE_SAMPLE` | 收到时已超过人员工作区失效时间；不可把旧时间改成当前时间“补新”。 |
| `400 POSITIONING_SAMPLE_INVALID` | 缺精度、坐标系 / 日期 / 字段不合规；核对协议映射。 |
| `503 POSITIONING_DISABLED` | 服务端尚未配置已启用设备。 |

单条请求上限 16 KiB。服务端仅保留当前进程每设备最新点并拒绝重复 / 乱序；没有轨迹持久化或跨重启去重台账。

## 4. 页面显示与联调

页面使用当前登录会话读取 **GET `/__management/positioning?projectId=…`**；必须具有项目成员资格、读取及模型查看权限，并逐条遵循现有人员记录权限。此接口不接受设备 token 作为人员查看权限。响应只包含可见人员的设备配置状态和最新样本，不含密钥或其他项目数据。

打开平台对应项目后，人员页显示网关连接状态。服务器上报 → 页面每 2 秒刷新 → 实测点进入已保存工作区的判定；切项目、退出 / 撤权会停止或拒绝旧请求结果。

现场验收顺序：

1. 用测量已知点核对定位点与模型坐标、时间和水平误差。
2. 到工作区内部，确认“实测 / 区域内”。
3. 走到边界附近，误差圆跨界时应显示“待核实”，不能强行判为区内。
4. 在安全可控的测试区移动到工作区外，确认页面“实测越界”提示。
5. 断开设备上报，超过失效时间后应显示“定位过期”，不能继续显示正常在岗。
6. 刷新网页可重新读取本次服务运行期间的最新样本；重启后恢复等待定位。重新绑定人员后旧凭据应拒绝上报。

当前“报警”是页面越界状态提示，**没有短信、声光器、微信推送、后台持续告警任务或持久化报警台账**。页面关闭后，服务端仍可收位置但不会独立发送报警；如需全天候告警，下一阶段应实现服务端持续规则任务和告警确认 / 消除记录，再接现场声光设备。

## 实现与验证边界

服务端模块：`server/management/positioningGateway.ts`；受控路由：`server/managementStore.ts`；前端轮询：`src/railSafetyPositioningClient.ts`；围栏判定仍复用 `src/railSafetyPositioning.ts`。

自动测试覆盖独立设备认证、项目 / 人员绑定隔离、账号权限、凭据不泄漏、重复 / 乱序 / 过期与超前时间、格式精度校验、重启清空、只读轮询取消及迟到响应抛弃。自动测试采用隔离样本，不代表现场硬件或坐标标定已经验收。
