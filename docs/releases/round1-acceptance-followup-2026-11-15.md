## 已确认原因与修订

### 1. Globe 保留契约

源码复核确认：`SurfaceEditScene` 销毁时保留绑定于 Globe 的禁用、非空裁剪集合，避免地形 LOD 继续引用已销毁 GPU 资源；最终由 Viewer/Globe 的销毁链释放。该策略及“同一集合禁用但未销毁”的 CPU 断言在指定基线中已存在。

新增浏览器脚本原先要求该集合为 `null`，与既有契约冲突。该失败不能据此认定生产资源泄漏。修订保持产品销毁策略，并加强实际生命周期验证：

1. 首次创建地表时捕获真实集合引用并确认自有身份，不能在销毁前才捕获一个替代对象。
2. 工具销毁后，核验绑定的仍是原引用、集合禁用且未销毁、非空几何与此前快照相同；保留 planes 清除、mesh 清理、地面状态恢复和错误数组断言。
3. Viewer 销毁后，对保留引用检查 `isDestroyed() === true`；再次调用销毁仍安全，不访问已销毁场景或集合内容。
4. CPU 测试补充真实 `Globe.destroy()` 对该集合的最终释放断言。此测试不等于真实地形 GPU 销毁验收。

### 2. Windows 文件链接能力

原复合用例先创建文件 symlink，Windows 权限不足时会连带阻断普通路径或日志脱敏断言。现在拆分为：

| 用例 | 要求 |
| --- | --- |
| 普通 HTTP、权限、URI、越界路径、旧日志脱敏 | 始终执行，不依赖 symlink 创建权限 |
| 目录链接、摄影挂载根替换、诊断目录及记录链接 | Windows 使用目录 junction，其余平台使用目录 symlink；失败仍报告失败 |
| 两项独立文件 symlink 边界 | 实际创建成功则必须执行原边界断言；只有 Windows 创建阶段的 `EPERM/EACCES/ENOTSUP` 可明确记为环境跳过 |

跳过原因明确注明文件链接边界断言未执行，不冒充该机安全验证通过。Linux、未知错误、已成功证明具备能力后的第二次创建异常都不能被跳过。测试 helper 的注入矩阵覆盖这些限制；有权限 CI 仍需执行真实文件链接测试。没有提升机器权限、修改系统策略、关闭文件保护或修改产品服务。

任务书明确 TEMP/TMP 放在候选源码树外，三个候选业务数据根继续隔离。旧地表脚本只增加控制台位置、HTTP 错误 URL/状态及失败请求记录，原场景断言不变；这些记录用于下一次定位 404，当前没有故障已修复的结论。按本机已确认的编码器能力使用既有 `FFMPEG_VIDEO_ENCODER` 参数，不将软件媒体用例记作硬件 AR。
