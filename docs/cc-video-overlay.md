# CC 空三视频融合

本模块以航拍视频为主画面，按 CC 空三优化后的相机位姿渲染已经定位的 CAD 和工程模型。视频中的字幕属于画面内容；平台读取 CC XML 中的相机信息，不要求外置 SRT，也不对烧录字幕进行 OCR。

## 使用流程

1. 在平台导入并定位 CAD、工程模型，核实模型与空三成果使用的坐标及高程基准。
2. 在“视频 AR”选择原视频，展开“从视频抽帧 → CC 空三”，设置范围与间隔或数量。默认每秒一张、保留原始分辨率；输出 JPEG 和 `video-frame-manifest.json`。把照片送入 CC，保持文件名，导出包含优化位姿和相机标定参数的 XML。
3. 在“视频 AR”导入原视频及对应 XML。保留原视频的画幅、裁切和方向；重编码、裁切或变速后的录像需要重新核对映射。
4. 平台抽帧后自动关联每张照片的实际解码时间；重开时可导入随照片保存的时间清单。CC 剔除照片不会压缩时间间隔。外部等间隔抽帧仍可手填首张时间、间隔和编号增量，不能把抽帧序号直接解释成视频帧号。
5. 进入融合后，若倾斜摄影与视频也有公共偏差，先只勾选倾斜摄影，开启“视频相机校正”，核对建筑、道路等不同位置和高度的地物。公共配准核验后，再勾选 CAD／工程模型，按需使用“叠加对象位置微调”；已有对象微调会保留。
6. 使用进度条检查视频开头、中间、结尾及转向段的暂停画面。点击“缓存后播放”或“生成完整融合缓存”，等待全部画面准备完成，再连续播放。生成时间可以长于视频时长；播放保留源视频每帧节奏与原分辨率。
7. 离开“视频 AR”或进入现场工作台、机械工具会退出融合并恢复地图。已完成的融合缓存保留在同一浏览器、同一站点的本机存储中；再次打开同一方案可复用。

## 保存与恢复

- 每次新视频融合形成可命名的方案，开始融合后自动保存，微调后延迟合并保存；退出立即提交最新快照，后台完成保存。首次上传包含视频、XML 和抽帧清单；同方案后续修改只更新参数，不重复上传大视频。
- “融合方案”列表可打开已有方案，或载入副本再开始融合生成独立方案。重新打开前会等待当前保存完成。方案持久化仍服从资料库写入权限；保存失败保留当前页面草稿并显示重试入口，未完成首次上传时不要关闭页面。
- 所有读取仍按录像、模型、文件权限分别检查；引用不授予底层文件访问权限，无权访问时不会删除方案中的依赖并覆盖原方案。
- 对象选择和微调按录像保存，不写回工程模型的原始定位；不要将视频微调误认为修正了项目控制网。
- 相机校正单独保存六个参数、启用状态及固定首帧基准。旧方案默认禁用，不会把已有对象微调自动换算成相机校正。
- 重新打开只恢复暂停状态，用户进入融合后才接管主视角。
- 融合中的视频相机不会覆盖平台保存的正常地图视角。
- 旧视频投影资料保留兼容能力；现场工作台的历史录像播放器选择 CC 融合记录时，会提示回到“视频 AR”打开。

## 数据和显示边界

- 无时间戳的空三照片必须有可靠的抽帧时间对应关系。平台时间清单支持非等间隔实际帧时间，并通过视频大小与首／中／尾内容指纹校验源文件；它不是整文件真实性证明。外部重命名或拼接数据不能用固定间隔猜测。
- 稀疏空三相机之间采用插值，快速运动、变焦、滚动快门、时间误差和镜头畸变均可能造成局部偏移。整体位置微调不能消除这些误差。
- 二维 CAD 需要正确的空间定位及工程标高。贴地或贴模型显示的图纸应检查其真实三维几何是否满足视频融合用途。
- 现场遮挡使用已加载的网格倾斜摄影提供深度，需在“地表与建筑遮挡”中启用并指定参照。视频中的实时车辆、人员及成果采集后发生变化的物体，没有对应几何时不能产生准确遮挡。
- 本版接收单一透视相机组、`XRightYDown` 相机坐标和 WGS84 经纬度 XML（EPSG:4326／4979）。其他投影坐标系、多相机组或非零 Skew 会明确提示，不会静默套用相机参数。

## 模型在地图中对齐、在视频中错位时

先保留工程模型与倾斜摄影已经核对的定位。二维 CAD 在某一画面中大致吻合，仍不能单独验证不同高度构件的透视关系；还需检查视频时间、相机内外参数与场景的坐标基准。

如果本次 CC 空三对应的倾斜摄影成果在平台中做过整体位置或高程校正，可在“视频与三维场景的坐标关联”中明确选择这份已加载、已保存的成果。系统将它保存的 `modelMatrix` 同步给原始空三相机的位置和方向，模型、CAD 的原定位与比例保持不变。只使用应用层整体定位矩阵，不再次应用瓦片 `root.transform`；当前支持平移和旋转，拒绝缩放、镜像与剪切。

默认不关联，也不自动选择最近图层。必须确认是与本次空三使用同一成果基准的数据，不能仅因它与工程模型在地图中相邻就关联。相机变化会影响所有叠加对象的画面投影；若原矩阵为单位矩阵，这项关联不会改变画面。已有 CAD 或模型的独立 AR 微调也需一并核对。

关联随视频保存定位快照；若该成果的已保存矩阵后来改变，需点击“重新读取成果定位”后重新核验。成果未加载或失去访问权限时，不继续使用过期关联播放；不会默默切换到另一份成果。

如果倾斜摄影叠加到视频中也存在重影，可使用“视频相机校正”调整公共配准。相机东移、北移、升高以固定首帧位置的当地东、北、天方向计量；正航向为顺时针，正俯仰为抬头，正横滚为右倾。数值确认后更新当前暂停画面，取消勾选保留数值并关闭校正，便于对比。

这六项参数对整段相机轨迹施加同一个刚体变换：首个空三相机经过成果关联后的姿态作为固定基准，后续相机的位置和方向一起旋转、平移。因此旋转会改变远离首帧的相机位置，并非仅调整每帧云台朝向。开始可小幅调整位置和角度，观察分布在近远处的同名点，再核验首、中、尾及转向段；不能仅凭单个地物或单帧判断精度。镜头内参、时间对应或局部轨迹变形仍需针对数据本身核验。

“重置相机校正”只清零并关闭相机校正，保留 CAD 和模型已有的对象微调。相机基准随方案固定保存；更改抽帧时间、高程或成果关联不会悄悄重建它，需重新核验，确需采用新的首帧基准时使用该重置按钮。更换视频或 XML 则按新方案清除相机校正及对象微调。相机与对象两项独立校正可能叠加，校准公共配准后应检查已有对象微调是否仍适用。

CC 对地理参考系默认采用相应 datum 的椭球高；这属于 [CC 的高程约定](https://docs.bentley.com/LiveContent/web/ContextCapture%20Help-v18/en/GUID-B6BA56E7-6124-4D90-9D00-D8A2FE7ACE20.html)，不是说 EPSG:4326 本身定义了垂直基准。新方案默认保留 XML 原始高程，旧方案的手动高差继续保留。只有已核实原数据基准时才使用手动改正，避免与成果整体定位校正重复添加同一高差。

仍有偏差时，在问题画面暂停，点击“导出配准诊断”。JSON 包含视频时间、原始空三相机、成果关联后的相机、相机校正参数／固定基准／变换矩阵、最终校正相机、内参、畸变，以及有权访问的所选对象／倾斜摄影的保存矩阵、显示矩阵、比例和微调值，不包含原视频或模型文件。关联过期时仍可导出诊断。凭这些实际数值排查，不以修改已对齐的模型定位来补偿未知相机误差。

## 地下构件与实景遮挡

视频画面本身没有三维深度。未开启实景遮挡时，工程模型中的桩基、地下构件和被建筑挡住的部分仍会渲染；隐藏地图底图并不会自动识别地下部分。

在“地表与建筑遮挡”勾选启用，选择同一现场、已定位并已与视频校准的网格倾斜摄影，重新点击“开始融合”。也可点击“使用相机关联的倾斜摄影”明确采用当前关联成果。参照只提供遮挡深度，地表和建筑前方的工程几何保留，后方几何被遮住，视频颜色仍然可见。无需在“叠加对象”里再勾选参照纹理。

遮挡选择与相机坐标关联、叠加图层选择分别保存。旧方案默认关闭，避免自动采用另一份同名或不同航次成果。遮挡参照使用地图原定位，不参加对象整体平移；如这份倾斜摄影已有非零视频对象微调，需先关闭遮挡并核实、恢复该图层微调后再启用。模型和 CAD 的原定位、已有微调及相机校正不会被自动改变。

播放过程中会继续加载更精细的倾斜摄影瓦片。已有地表覆盖当前视角时，使用它持续遮挡，待细节就绪后替换，不因后台请求反复隐藏整层模型。某块细节加载失败也不会永久关闭整段叠加；已有地表仍可用于遮挡，并显示相应提示。首次加载、跳转到尚无可用地表的新区域或当前可见区域存在未加载分支时，会暂停视频并保持上一幅已完成的融合画面，等待当前视角地表就绪后继续，避免地下构件透出或模型闪没。首次尚无完整帧时显示等待状态。显示与导出只采用同一解码帧、相机时间和完成的渲染结果，不把旧深度套在新视频上。

参照被卸载或失去访问权限后需重新加载或关闭遮挡，不会替换为另一份成果。退出融合会恢复参照原有材质、样式、加载设置和地图显示状态。此次修改不改变模型定位、CAD 微调或空三相机参数。

遮挡的精度与范围取决于参照几何及视频配准。需要覆盖相应地表的连续三角网；缺失地面、网格孔洞、年代不同或坐标偏移仍可能造成漏遮或误遮。本版不将点云当作连续地表，不自动使用零米高程切割；参照存在剖切或自定义顶点形变时会提示先处理冲突。地下构件仍保留在原模型中，地图查看和后续分析不受此次视频遮挡影响。

## 完整缓存播放与资源释放

版本 `2026.10.20-R4` 将展示播放改为先完整计算、后播放。编辑状态只按所选时间生成暂停画面；点击播放后，Mediabunny/WebCodecs 连续解码源视频，每一帧按对应时间驱动相机、工程模型、遮挡、标注及展示效果，完整合成后才编码。不会使用默认30fps重采样，也不跳过计算较慢的源帧。VFR保留原节奏；WebM时间基为1ms，编码时间有毫秒级量化，区间边界会裁剪首尾帧时长。

编码结果以1MiB写入块流向OPFS磁盘缓存，不把整段压缩视频积累在内存。完成封装并关闭文件后才发布可播放缓存。缓存键包含视频/XML/时间清单的分块内容指纹、资源版本与定位、对象选择、配准、时间区间、标注及效果；方案改名、拖动进度、播放倍速不要求重算三维画面。每方案最多保留两个完成版本。浏览器清除站点数据或改变访问端口后，原缓存不可直接复用，方案资料仍由项目资料库保存。

缓存生成后即结束AR三维会话，释放合成器、模型副本、镜头校正与遮挡资源、源视频解码器及监听器。普通播放器独立播放已完成的文件，不再为每帧等待Cesium。主地图恢复原相机、尺寸、渲染设置和交互；AR改变尺寸的附属拾取缓冲只释放可重建附件，不销毁主Viewer或共享模型。

退出立即取消本次准备任务，阻止迟到结果重新加入场景；重新进入前等待该任务收尾。清理报告记录未完成或失败项，可随“导出配准诊断”取得。瓦片按Cesium正常渲染生命周期回收，不能把一次`trimLoadedTiles()`当作内部解析队列已经取消。重复进入退出的验收应比较同一视角下的帧耗时、任务和事件监听数量，不能仅凭内存瞬间归零判断。

编码使用高质量VP9，保留源显示尺寸，备用码率随源帧率、像素量及源码率设置；不是数学无损编码。实际编码、解码能力取决于浏览器和驱动。云端SwiftShader合成场景测试不代替用户电脑、原视频和现场模型的性能验收。

## 抽帧与导出

- 抽帧最多5000张，保留原始分辨率。文件夹方式逐张写入照片、时间清单和POS数据；ZIP回退保留128MiB内存上限。抽帧使用独立解码器，退出取消任务并禁止迟到的时间清单覆盖新会话。
- “导出融合视频”使用与缓存播放相同的源帧流程和原分辨率，已有有效缓存时直接下载WebM；不再提供降低帧率或分辨率的性能捷径。首次完整计算期间可以取消或退出。
- 默认保留源音轨，音轨存在但无法解码/编码时明确报错，不静默生成无声结果。用户取消“保留原视频音轨”时才主动去掉音轨。
- 缓存路径不沿用旧512MiB或一分钟4K预检限制；实际容量受浏览器存储配额和磁盘空间限制。配额不足、编码不支持或某帧模型/遮挡未就绪时停止生成，不发布半成品，不自动降低画质。

## 缓存与退出回归

`tools/verify-video-overlay-native-cache.mjs` 使用合成60fps/VFR/旋转视频、ffprobe和真实浏览器解码验证帧数、时间戳、尺寸、音轨、取消、跨刷新复用；`CONTROLLER=1` 增加普通播放进入缓存、渲染资源释放、五次退出复用和生成中退出。65秒4K用例仅验证能到达首帧且可取消，不代表完整长片已编码。`tests/video-overlay-render-targets-browser.mjs` 验证真实Cesium4K拾取附件释放后可以按地图尺寸重建并继续拾取模型。

## 本次验收范围

本次开发依据现有 Cesium 工程、用户提供的空三 XML 和位置 CSV。尚未取得对应原视频，不宣称已经通过该航次的实景贴合或精度验收。正式验收应提供原视频及可核对的抽帧时间，选取分布在不同位置与深度的同名点，在首、中、尾和转向片段检查偏移；同时验证暂停、拖动进度、离开恢复和保存重开。
