# CC 空三视频融合

本模块以航拍视频为主画面，按 CC 空三优化后的相机位姿渲染已经定位的 CAD 和工程模型。视频中的字幕属于画面内容；平台读取 CC XML 中的相机信息，不要求外置 SRT，也不对烧录字幕进行 OCR。

## 使用流程

1. 在平台导入并定位 CAD、工程模型，核实模型与空三成果使用的坐标及高程基准。
2. 对原始视频抽帧，在 CC 中完成空三，导出包含优化位姿和相机标定参数的 XML。
3. 在“视频 AR”导入原视频及对应 XML。保留原视频的画幅、裁切和方向；重编码、裁切或变速后的录像需要重新核对映射。
4. 按真实抽帧过程设置首张照片对应的原视频时间、抽帧间隔。编号是抽帧序号时，不能把编号直接解释成视频帧号。空三剔除的照片仍占原抽帧序列中的时间位置。
5. 进入融合后，若倾斜摄影与视频也有公共偏差，先只勾选倾斜摄影，开启“视频相机校正”，核对建筑、道路等不同位置和高度的地物。公共配准核验后，再勾选 CAD／工程模型，按需使用“叠加对象位置微调”；已有对象微调会保留。
6. 检查视频开头、中间、结尾以及转向段，确认时间同步和定位。离开“视频 AR”或进入现场工作台、机械工具会退出融合并恢复地图。

## 保存与恢复

- 原视频、XML 与融合设置使用既有本机资料库保存。首次保存包含文件，后续位置或时间微调仅更新该录像的设置。
- 对象选择和微调按录像保存，不写回工程模型的原始定位；不要将视频微调误认为修正了项目控制网。
- 相机校正单独保存六个参数、启用状态及固定首帧基准。旧方案默认禁用，不会把已有对象微调自动换算成相机校正。
- 重新打开只恢复暂停状态，用户进入融合后才接管主视角。
- 融合中的视频相机不会覆盖平台保存的正常地图视角。
- 旧视频投影资料保留兼容能力；现场工作台的历史录像播放器选择 CC 融合记录时，会提示回到“视频 AR”打开。

## 数据和显示边界

- 无时间戳的空三照片必须有可靠的抽帧时间对应关系。不等间隔、重新编号或多段拼接的数据不能用一个固定间隔推算，本版需先整理成可核对的等间隔抽帧序列后使用。
- 稀疏空三相机之间采用插值，快速运动、变焦、滚动快门、时间误差和镜头畸变均可能造成局部偏移。整体位置微调不能消除这些误差。
- 二维 CAD 需要正确的空间定位及工程标高。贴地或贴模型显示的图纸应检查其真实三维几何是否满足视频融合用途。
- 这是透视叠加。现场建筑、树木和车辆对工程模型的真实遮挡，需要另外提供可用于遮挡的现状几何或深度数据。
- 本版接收单一透视相机组、`XRightYDown` 相机坐标和 WGS84 经纬度 XML（EPSG:4326／4979）。其他投影坐标系、多相机组或非零 Skew 会明确提示，不会静默套用相机参数。

## 模型在地图中对齐、在视频中错位时

先保留工程模型与倾斜摄影已经核对的定位。二维 CAD 在某一画面中大致吻合，仍不能单独验证不同高度构件的透视关系；还需检查视频时间、相机内外参数与场景的坐标基准。

如果本次 CC 空三对应的倾斜摄影成果在平台中做过整体位置或高程校正，可在“视频与三维场景的坐标关联”中明确选择这份已加载、已保存的成果。系统将它保存的 `modelMatrix` 同步给原始空三相机的位置和方向，模型、CAD 的原定位与比例保持不变。只使用应用层整体定位矩阵，不再次应用瓦片 `root.transform`；当前支持平移和旋转，拒绝缩放、镜像与剪切。

默认不关联，也不自动选择最近图层。必须确认是与本次空三使用同一成果基准的数据，不能仅因它与工程模型在地图中相邻就关联。相机变化会影响所有叠加对象的画面投影；若原矩阵为单位矩阵，这项关联不会改变画面。已有 CAD 或模型的独立 AR 微调也需一并核对。

关联随视频保存定位快照；若该成果的已保存矩阵后来改变，需点击“重新读取成果定位”后重新核验。成果未加载或失去访问权限时，不继续使用过期关联播放；不会默默切换到另一份成果。

如果倾斜摄影叠加到视频中也存在重影，可使用“视频相机校正”调整公共配准。相机东移、北移、升高以固定首帧位置的当地东、北、天方向计量；正航向为顺时针，正俯仰为抬头，正横滚为右倾。数值确认后更新当前暂停画面，取消勾选保留数值并关闭校正，便于对比。

这六项参数对整段相机轨迹施加同一个刚体变换：首个空三相机经过成果关联后的姿态作为固定基准，后续相机的位置和方向一起旋转、平移。因此旋转会改变远离首帧的相机位置，并非仅调整每帧云台朝向。开始可小幅调整位置和角度，观察分布在近远处的同名点，再核验首、中、尾及转向段；不能仅凭单个地物或单帧判断精度。镜头内参、时间对应或局部轨迹变形仍需针对数据本身核验。

“重置相机校正”只清零并关闭相机校正，保留 CAD 和模型已有的对象微调。相机基准随方案固定保存；更改抽帧时间、高程或成果关联不会悄悄重建它，需重新核验，确需采用新的首帧基准时使用该重置按钮。更换视频或 XML 则按新方案清除相机校正及对象微调。相机与对象两项独立校正可能叠加，校准公共配准后应检查已有对象微调是否仍适用。

CC 对地理参考系默认采用相应 datum 的椭球高；这属于 [CC 的高程约定](https://docs.bentley.com/LiveContent/web/ContextCapture%20Help-v18/en/GUID-B6BA56E7-6124-4D90-9D00-D8A2FE7ACE20.html)，不是说 EPSG:4326 本身定义了垂直基准。新方案默认保留 XML 原始高程，旧方案的手动高差继续保留。只有已核实原数据基准时才使用手动改正，避免与成果整体定位校正重复添加同一高差。

仍有偏差时，在问题画面暂停，点击“导出配准诊断”。JSON 包含视频时间、原始空三相机、成果关联后的相机、相机校正参数／固定基准／变换矩阵、最终校正相机、内参、畸变，以及有权访问的所选对象／倾斜摄影的保存矩阵、显示矩阵、比例和微调值，不包含原视频或模型文件。关联过期时仍可导出诊断。凭这些实际数值排查，不以修改已对齐的模型定位来补偿未知相机误差。

## 本次验收范围

本次开发依据现有 Cesium 工程、用户提供的空三 XML 和位置 CSV。尚未取得对应原视频，不宣称已经通过该航次的实景贴合或精度验收。正式验收应提供原视频及可核对的抽帧时间，选取分布在不同位置与深度的同名点，在首、中、尾和转向片段检查偏移；同时验证暂停、拖动进度、离开恢复和保存重开。

## 开发验证

生产构建及相机／资源／坐标关联回归：

```bash
npm run build
node --experimental-transform-types --test src/ccCameraTrack.test.ts src/ccSceneRegistration.test.ts src/ccCameraRegistration.test.ts src/videoOverlayResources.test.ts src/videoArCamera.test.ts src/videoArCameraFrame.test.ts src/videoArHeight.test.ts
node tests/video-overlay-access-regression.mjs
```

真实 Chromium／Cesium WebGL 回归使用合成视频和真实 GLB（非零源原点、2.5 倍比例），用不同高度的 CAD 对照点检查多个视频时刻的投影像素邻域，并验证透明背景与透明度、播放和跳转同步、ENU 微调与撤销重做、保存恢复不累积、退出场景恢复、定位范围外隐藏、缩放后的投影一致性和主页面入口。关联测试另验证同一矩阵同步相机与场景、定位快照保存恢复、变更拦截与诊断导出。相机校正测试使用独立矩阵推导核对非零平移与复合旋转，检查固定首帧基准、非首帧保存重开、启停对比、旧方案兼容和重置时保留 CAD 已有的 29 米微调。像素邻域检查用于排除明显渲染错位，不是子像素精度验收。测试还成功解析提供的 31 张影像空三 XML；这仅验证数据读取，不代表原航次的贴合精度。
