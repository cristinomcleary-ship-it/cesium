# CAD 交互、导入及场景目录一致性

本次修复针对普通场景卡顿、可见 CAD 不在场景管理目录、CAD 导入极慢或无法完成三个问题。代码基于 `493b5dada42e4740e5d648037d71de756f87dea0`，保留之前的几何内存保护和资源生命周期修复。本文件的预算与验证结果取代 `render-stability-20261025.md` 中初次补丁的对应配置。

## 可复现原因

1. **源缓存与 Worker 预算被混为一谈。** 初次补丁将贴地待分组缓存缩至 4096 点；空间格交错、单图元点数较多时，压力驱逐把一个小格移入 overflow 后立即发出，反复生成极小 Primitive。十万项、每项 128 点、32 个交错格的用例因此生成十万个批次。每批仍要创建、合并、上传，且完成后都参加常规场景更新，既拖慢导入，也拖慢不使用 AR 时的交互。
2. **场景挂载早于目录登记。** 原入口先把集合加入地球，等所有图元 ready 后才登记 `imports`；场景目录只读取 `imports`。其间既看得到图纸，又没有对应管理项。新导入还在编译前保存资料，资料库可再次恢复同一 ID，出现两个场景集合与一个目录条目的竞态。
3. **等待链与主线程阻塞。** 手动导入等待整个资料库的串行恢复；某份图纸慢会阻挡新的导入。管理页面主动停止渲染循环时，编译等待仍按墙钟计时，会误报超时。大 `.cadimport` 的 JSON 解析也同步发生在主线程。普通鼠标移动还会逐事件执行地形求交，仅用于底部坐标读数。

## 处理方式

- 源描述缓存独立保留 131072 点，压力驱逐优先聚合兼容的小格，不再退化为每个图元一个 Primitive。普通渲染批次预算为绝对高程 32768 点、贴地/模型依附 4096 点；共享场景仍最多两个在途编译批次。超大完整面继续独占编译，不截断、不降低精度；表面采样仍独立限制为 8192 点分组。
- 转换阶段按约 10ms 时间片让出主线程。大于等于 1MiB 的 `.cadimport` 在一次性 Worker 中读取、解析和验证；取消、格式错误和通信失败均明确结束。返回对象仍有结构化克隆开销，这不是零主线程成本或无限文件大小支持。
- 加载中的 CAD 使用独立登记表，立即进入场景管理，显示进度并支持隐藏、取消；尚未完成的资源不冒充可供 AR/采样使用的已就绪资源。同 ID 的恢复互斥，完成后交接给正式目录，失败或取消只回收本次资源。新图纸成功准备后再持久化，避免每次编译失败都留下一份待恢复的资料。
- 手动导入只等资料目录读取，不再等待全部图形恢复。暂停渲染时保留待加载任务，恢复渲染后继续；主动暂停的时间不消耗编译超时预算。
- 底部鼠标坐标按 100ms 合并采样，镜头移动期间暂停，停止后用最终鼠标位置和相机刷新。保留真实地形高程，测量、放置模型及其他显式拾取不受影响。

## 验证证据与边界

| 同源合成用例 | 初次补丁 | 当前修复 |
| --- | ---: | ---: |
| 4096 条闭合曲线、每条 128 个源点、32 个交错空间格：真实 loader 创建的 Primitive 数 | 4096 | 160 |
| 十万项、每项 128 点、32 个交错格：贴地分组数 | 100000 | 3136 |
| 十万项、每项 128 点、129 个交错格：贴地分组数 | 100000 | 3249 |

闭合曲线对照的 4096 个逻辑图元、524288 个原始顶点均保留；含闭合点的逻辑顶点为 528384。真实 Cesium 打包对照：绝对高程 32768 点约 13.1MB、贴地 4096 点约 10.9MB，测试限制单次 packed buffer 小于 16MiB。源缓存、打包数组、合并数据和 GPU 资源是不同的成本，以上不是总进程内存或浏览器帧率测量。

真实浏览器的独立非 WebGL 夹具 `tools/fixtures/cad-import-performance.html` 六项检查通过：7,740,550 字节、60000 图元的文件经模块 Worker 完整读取，读取期间界面计时器继续运行；取消与错误格式明确结束；十万图元绝对高程与贴地分组分别为 420 与 3136 批，所有项目恰好输出一次且满足批次预算。该页不读取工程资料，不代替本机原始场景的 GPU 验收。

最终 817 项自动化测试全部通过，无失败、取消或跳过；TypeScript 检查、生产构建与 `git diff --check` 通过。构建仍有既有的大 chunk 警告。测试覆盖大规模交错分组、实际 Cesium 打包、Worker 读取与取消、加载登记和资料库编排、暂停恢复及原有机械/视频/显示等回归。现有云端浏览器无法初始化 Cesium WebGL，因此不宣称已验证用户显卡上的 FPS、内存峰值或原始图纸导入耗时。任何既有重复资料不自动删除；应在本机目录中核对真实资源与记录后由用户选择保留项。

## 本机部署和验收

按 `CODEX_LOCAL_DEPLOY_CAD_TILT.md` 的保护流程更新，并以本次交付的完整提交 SHA 为准；不要再次部署初次补丁 `493b5da`，也不要套用旧脚本默认分支。核实原工程与运行服务，先创建并核验 GitHub 代码备份；保留本机独有修改、数据目录、环境变量和原访问地址，安全整合、暂存构建后使用原服务方式安装和重启。

使用同一份原始图纸、相同图层与相机范围进行以下检查，不能通过减少图层、降低视频/模型质量或换小图纸代替：

1. 不进入 AR，完成平移、缩放、旋转、拾取，记录可测的帧率和交互响应；没有部署前基线时明确说明。
2. 新导入和资料库恢复时，CAD 应在加载开始后立即进入目录；隐藏、取消、同 ID 重复恢复、加载中删除不得留下孤立或重复集合。隐藏资料恢复时不应闪现。
3. 分别验证 DWG 与 `.cadimport`、绝对高程/贴地/依附模型、长线/闭合线/复杂面/文字，核对位置、图元和拾取完整性。错误文件不保存成一份新的有效图纸。
4. CAD 加载中切换到不渲染三维的管理页面，停留超过一分钟后返回，任务继续或明确取消，不能因为主动暂停而误报编译超时。
5. 保持原资料及正式方案不变，检查 AR 进入退出、机械倾覆和侵限、剖切开挖、显示分组及项目恢复。
6. 报告实际部署 SHA、GitHub 备份核验、服务 PID/原 URL、实测导入耗时及上述结果；不能用云端 CPU 测试或构建成功代替现场验收。
