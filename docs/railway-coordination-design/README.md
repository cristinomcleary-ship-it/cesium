# 铁路施工统筹平台

设计参考为用户确认的铁路施工统筹 Demo。正式平台继续使用既有账号、项目、任务、机械、资料、检查、问题处置和 Cesium 场景；Demo 的虚构工点、人员、许可编号和浏览器演练数据不进入正式台账。

## 管理入口

| 入口 | 主要用途 |
| --- | --- |
| 今日管控 | 查看当前业务日期的作业、待核查条件、实施状态、待收工确认和未闭环问题，进入对应明细办理。 |
| 工点与计划 | 按工点、任务和日期组织安排，查看所属线路、里程和计划信息。 |
| 施工任务 | 查看任务的计划责任、作业条件、现场布置、过程记录、问题和完工资料。 |
| 现场三维 | 使用原 Cesium 场景查看机械、限界、防护区域和筛查结果，继续在右侧控制图层和显示效果。 |
| 检查与处置 | 使用已有检查、核查、整改、复核流程，保留责任人、证据和操作历史。 |
| 资源与档案 | 查看人员与岗位、机械、物资和任务资料；原有细分业务继续保留。 |

各入口均以当前账号可见数据为范围。没有查看或办理权限时，不以首页卡片、搜索、导出或任务联动绕过权限。

## 任务信息与办理

任务新增线路名称、区间或站场、里程范围、行别或股道、施工类型、作业窗口、适用许可依据编号和作业批次标识。作业窗口按北京时间填写，精确到分钟，开始和结束须成对填写，结束必须晚于开始，支持跨日。

本轮的“作业批次标识”是任务上的标签，不是独立批次实体。同一任务尚不支持独立保存多个批次的状态与确认记录；需要分别办理的作业，仍应建立各自任务。

实施中的任务可以登记暂停原因；恢复时需填写复核结果和恢复依据，服务器重新核查开工条件及未关闭的阻断问题，并保存暂停、恢复的操作历史。恢复失败时任务保持暂停。现场已确认的工程量、检查记录和风险记录不会随暂停清空。

收工与完成继续使用已有检查表、验收记录、完工条件规则以及“申请完成 / 确认任务完成”流程。任务详情按“计划与责任、作业条件、现场布置、过程记录、风险与问题、收工与归档”组织，不采用 Demo 中勾选即可演练归档的逻辑。

首页“导出管控清单”导出当前账号可见任务的 CSV，包含线路里程、批次标识、计划日期、北京时间窗口、许可依据编号、当前状态、负责人及未闭问题数。该清单是当前台账导出，不替代原有固定报告快照。资料归档与报告仍从“资源与档案”进入。

## 使用原则

1. 首页指标用于发现和进入待办；打开明细后，根据相应记录及权限办理。任务关联、模型绑定和状态显示均不等于现场条件已经满足。
2. 条件未配置、证据不足或数据未知时，显示待配置、待核查或缺项；不能因条目为空而显示全部通过。
3. 内部条件核查、外部许可记录和实际作业时段分别管理。内部确认及例外记录不替代适用的正式许可、登记、签认或调度手续。
4. 项目机械总数按设备唯一编号去重。机械未配置管控范围、未放置模型或同时关联多个任务时，不应漏计或重复计入项目总数。
5. 模型几何筛查作为待核实线索。问题单关闭不改变当前场景的几何关系；历史登记快照与当前配置分别保留。
6. 表单草稿、重复提交保护、修订冲突和操作审计继续使用既有机制。业务记录以服务器保存结果为准。
7. 人员定位接入继续暂缓。本轮人员管理使用已有资源、岗位安排及人工记录。

首页“当日计划作业”按所选管控日期和登记窗口统计，窗口使用开始包含、结束不包含的时段规则：作业在次日 00:00 结束时，不再算作次日作业。仅有计划日期的旧任务仍包含计划结束日。其余状态卡片展示当前账号可见的项目台账，并在页面注明统计范围。

## 部署与数据保留

更新范围以基线 `1bcaacd` 为准，通过增量补丁、改动源码及文件清单交付。在目标项目中先保存当前工作并备份现有数据库、上传文件及配置，再应用本轮源码改动。构建命令为 `npm run build`；需要重启包含管理后端的原服务。仅替换前端静态文件不能使新增服务端行为生效。

保留现有数据库、账号、环境变量、模型及上传目录；不使用 Demo 的存储数据覆盖工程数据。部署后的实际操作、不同角色访问和界面显示需要在目标环境核验。具体执行过的检查与尚未验证的范围见 [validation.md](./validation.md)。
