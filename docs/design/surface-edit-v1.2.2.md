# 地表开挖、土体补面与局部压平：设计及验收方案

基线：`v1.2.2`，备份提交 `60395aae96fc78753cdeef99e8f745e33d0a5903`；开发分支：`codex/surface-edit-v1.2.2`。本文件说明首期实现与待执行验收，不表示已部署或已通过用户本机 GPU 验收。既有功能保护及采样约束遵循 [AGENTS.md](../../AGENTS.md) 和 [开发兼容性约定](../DEVELOPMENT_COMPATIBILITY.md)。

## 1. 功能范围与工程含义

| 功能 | 实现行为 | 边界 |
| --- | --- | --- |
| 地表开挖 | 圈定选中摄影图层的范围，裁去范围内摄影，生成水平坑底及边界至坑底的土体侧壁；独立工程结构继续显示 | 坑底须低于全部外边界及保留区边界；可关闭坑底面；不生成放坡或支护结构 |
| 土体补面 | 新建承载材质的三角网格，封闭相应底面及侧边 | 贴图本身不能填补没有几何面的空洞；不推断未知地下土层，不修复全部原始摄影缺陷 |
| 局部压平 | 裁去指定摄影范围，按目标高程生成水平面及必要侧壁，替代树木、堆土等局部凸起的显示 | 属于可撤销的场景显示处理；不改写源摄影顶点或生成可导出的重建 3D Tiles |
| 显隐与恢复 | 保存多项方案，支持单项启停、编辑、定位、删除及场景显示列表联动 | 关闭一项只撤销该项效果，其他方案与临建遮挡继续有效 |

仅处理选定的 3D Tiles 摄影对象；工程 GLB、机械、临建、便道和硬化面不会自动被删除、移动或压平。若这些独立对象遮住观察范围，使用其原有显隐功能处理。摄影网格内部通常没有可单独识别的“树木对象”，因此本功能依赖明确选区，不承诺自动区分树木与铁路设施。

首期拒绝启用范围相交的地表方案，包括不同摄影图层上的相交方案，避免压平面盖住开挖面。相邻边界及有效保留区允许存在；孔洞必须严格位于外环内，不能相交、接触或互相包含。旧剖切占用摄影或地形裁剪接口时显示阻断原因，不替换旧裁剪。

**旧地下开挖的接口占用边界：** 旧工具关闭裁剪时可能只停用集合，仍保留摄影对象上的集合所有权。新模块按既有保护规则继续报告占用，不把“已停用”视为可以销毁或接管。先关闭旧地下开挖；若仍提示占用，重新加载对应摄影后再启用新地表方案。重新加载属于场景资源操作，不删除原始摄影文件、旧方案或工程模型；首期不支持两套开挖工具在同一摄影对象上直接叠加运行。

## 2. 操作与高程

1. 打开地图“地表编辑”，选择当前可见的摄影图层，填写方案名称及开挖/压平方式。
2. 绘制矩形或多边形，必要时添加内部保留区。多边形右键完成，Esc 取消；取消保留此前已确认范围。
3. 填写坑底或压平面标高，选择边界高程来源：有限摄影采样、已拾取高程或人工确认的统一标高。
4. 选择是否同步裁剪底层地形及显示底面，确认材质后“生成并保存”。成功后可逐项启停；关闭面板不删除已保存效果。

输入标高采用**场景椭球高**。生成器以首个边界点的经纬度及目标高程建立局部东—北—天（ENU）坐标系，设计面为该坐标系内的水平面；它不是整个大范围上恒定椭球高的曲面。测量成果中的工程标高、正常高或相对高程须先按项目已确认关系换算，不能直接混用。

有限采样读取原摄影边界，不遍历区域内部；水平底面和压平面由参数直接建网。矩形工具合成角点及树冠、屋面等拾取结果不能自动视为裸土地面高程，应采用边界采样或人工确认。土壁为竖向连接面，不代表实际放坡或地质分层；首期不计算土方量、边坡稳定性或结构安全结论。

## 3. 架构及状态提交

| 层次 | 主要文件 | 职责 |
| --- | --- | --- |
| 操作协调 | `src/surfaceEditController.ts`、`src/surfaceEditPanel.ts` | 权限及项目上下文、绘制、预算预检、取消、方案恢复与场景列表联动 |
| 采样与建网 | `src/surfaceEditJobs.ts`、`src/surfaceEditGeometry.ts`、`src/surfaceEdit.worker.ts` | 边界有限采样、拓扑检验、面积复核、水平面及侧壁网格、超时与过期结果丢弃 |
| 显示及裁剪 | `src/surfaceEditScene.ts`、`src/temporaryWorksClipping.ts` | 准备材质与网格、摄影裁剪贡献、可选地形裁剪、失败恢复及资源释放 |
| 参数存储 | `src/surfaceEditStore.ts`、`src/surfaceEditTypes.ts` | 版本化参数、数值及文档预算校验、原子保存、项目/用户隔离 |

执行顺序为：校验权限和当前上下文 → 估算单项及累计预算 → 必要边界采样 → Worker 建网 → 准备图像及三维资源 → 再次核对上下文、目标变换和显隐状态 → 同步提交效果与保存参数。采样、建网、材质准备或保存失败时释放候选对象，保留上一有效方案及原摄影。取消、关闭、切换项目或模式后，过期结果不得写回场景或新项目。

采样复用 `withPlanningSurface`：在短时独立场景中仅加载所选摄影，沿用其资源访问配置、模型变换及根变换；不将新增补面、工程模型或底层地形当作原摄影高程。任务信号与独立采样场景终止信号联动。保存已确认边界高程，显隐和刷新恢复不重新执行摄影采样。

摄影裁剪共用同一个 `TemporaryWorksClippingManager`，新贡献位于独立 `surface-edit` scope；临建与新模块的开关、清理和销毁互不影响。地形裁剪使用本模块自有集合，关闭时停用，避免旧地形 LOD 借用已销毁资源；同点数边界更新通过锁定 Cesium 版本的专用适配触发刷新。升级 Cesium 时须重新核验这一适配。

记录摄影 `modelMatrix` 与根变换指纹。摄影移动、旋转或变换改变后暂停旧方案，要求重新生成，禁止把旧世界坐标裁剪继续作用于新位置。

## 4. 材质及存储

无需提供土体贴图即可使用：地面内置土面、砂土和碎石，侧壁内置土壁和砂土；这些是展示材质，不是项目实测土层。可分别替换地面、侧壁图片并设置重复尺寸。自定义图片限定 PNG、JPEG、WebP，校验文件类型、内容及尺寸；恢复内置材质不修改源摄影纹理。

方案按当前浏览器、项目及用户存储，键前缀为 `cesium.surfaceEdit.v1:`，后接编码后的 `JSON.stringify([projectId, actorId])`。仅保存方案参数、边界高程及可选内嵌图片，不保存 Cesium/GPU 对象，不宣称跨设备同步。无查看权限时不加载对应记录；写入前重新核对当前项目、用户及编辑权限。

保存只对对应键执行一次 `setItem`。配额不足、文档损坏、未知版本或字段不兼容时明确报错，不清库、不静默重置、不覆盖损坏原件。浏览器实际可用配额可能低于本功能文档上限。项目数据库、旧临建记录、IndexedDB、OPFS、原始模型和私有资源路径不因此改写。

## 5. 工作量预算

以下是代码当前的开发期停止阈值，**尚不是用户设备的性能保证或工程精度承诺**。应使用代表性真实摄影数据实测后确认发布配置；预算相互独立，先达到任何一项即停止，不能把网格顶点数等同于摄影采样数。

| 范围 | 当前代码限制 |
| --- | --- |
| 保存方案 | 每个项目/用户上下文最多 32 项；含关闭方案累计边界最多 4,096 点 |
| 单项范围 | 外环与孔洞合计最多 512 点、最多 16 个保留区；交互绘制累计最多 256 点 |
| 摄影采样 | 单任务累计最多 512 点，每批 16 点，批次顺序执行；无自动重试 |
| 自适应接边 | 最多细化 6 层；边长控制值 20 m、中点高程插值误差控制值 0.25 m；不能满足时停止，不静默放宽 |
| 采样输出 | 最多 512 个边界点，同时受项目剩余点数限制；初始最低估算超限时不创建采样场景 |
| 网格输出 | 单任务最多 6,144 顶点、3,072 三角面；拓扑工作量估算上限 1,100,000 |
| 局部几何范围 | 局部 X、Y 跨度各不超过 10,000 m；边界与设计面高差不超过 1,000 m；有效面积至少 0.01 ㎡ |
| 几何内存估算 | 2 MiB，包含数值缓冲和代码规定的临时数组估算系数；不是浏览器/显存总内存上限 |
| 裁剪贡献 | 新 scope 最多 32 个贡献、4,096 边界点、1,024 裁剪多边形，累计拓扑估算不超过 1,000,000；不改变旧临建合法记录范围 |
| 时间与后台执行 | 建网 Worker 最多 15 s，整次生成最多 30 s；无 Worker 时只允许最多 64 点的受限回退 |
| 图像 | 单张解码前文件最多 2 MiB，宽高各不超过 2,048 px；图像解码最多 10 s |
| 方案文档 | 含图片编码的 UTF-8 JSON 最多 16 MiB；所有图片共同占用该预算 |

用户任务串行处理；生成前检查方案数、累计范围和当前修改项可用余量。分批不能绕过总量预算。未加载或缺失高程不按零补齐；达到预算时提示缩小范围、减少细碎边界、合理分区或填写已知标高。独立摄影采样器还设有 96 MiB 瓦片缓存及 64 MiB 溢出额度，它们不等于进程或 GPU 总内存约束。

## 6. 既有功能保护与 AR 取舍

首期地表编辑用于主三维场景。进入视频 AR 面板、拾取、实时融合或缓存相关场景操作时，暂停本模块补面与自有裁剪；最后一个占用操作结束后按当前方案、权限及项目恢复。**首期 AR 画面及视频导出不包含新开挖或压平效果**，不改变旧缓存签名或标注分层语义。

共享调用点及重点回归：

| 调用点 | 应保持的行为 |
| --- | --- |
| `main.ts` | 原场景显示目录、摄影图层、项目/账号权限、模型编辑入口及地图操作；新入口独立接入 |
| `temporaryWorksClipping.ts` 及其 GLB/道路/硬化调用方 | 旧多方案并集、显隐、删除、外部裁剪阻断、异步准备及损坏资源恢复 |
| `subsurfaceTools.ts` | 原剖切/地下工具继续拥有自身集合，不误关新模块地形集合；接口占用明确提示 |
| `videoModelOverlay.ts`、`videoArFusion.ts`、场景隔离适配 | 嵌套暂停可重复释放，异常及取消后恢复当前状态；旧视频、模型、相机和标注功能保持兼容 |
| `temporaryWorksScene.ts` 采样接口 | 原采样行为保留；新调用只增加自身预算及取消控制，不修改旧方案采样含义 |

## 7. 本机验证及发布条件

按 [本机部署任务](../../CODEX_LOCAL_DEPLOY_SURFACE_EDIT.md)，在必要的候选检出目录使用合成数据或已有独立测试项目运行，真实素材只读引用；不得复制生产数据或浏览器资料作备份。使用 Node.js 24+ 及仓库锁文件。以下命令是检查入口，不是通过记录：

```bash
npm ci --no-audit --no-fund
node tools/run-temporary-works-regression.mjs all --output output/surface-edit-regression
npm run build
node tests/model-placement-regression.mjs
git diff --check
```

浏览器专项需要可运行的 Playwright 与 Chromium/Chrome。按本机安装位置设置 `PLAYWRIGHT_MODULE`、`BROWSER_EXECUTABLE`；不要为运行检查随意升级产品依赖。

```bash
node tests/surface-edit-panel-browser.mjs
node tests/surface-edit-browser.mjs
node tests/model-edit-appearance-browser.mjs
node tools/verify-video-overlay-spatial.mjs
```

面板脚本仅验证隔离 DOM。地表浏览器脚本自行启动隔离 Vite 服务，使用合成 3D Tiles 和工程 GLB，报告默认位于 `output/surface-edit-browser/report.json`；其默认参数启用 SwiftShader，不能作为真实硬件 GPU 性能验收。硬件复测须通过该脚本支持的 `BROWSER_LAUNCH_OPTIONS` 提供实际浏览器启动配置，并核对报告中的 renderer。AR 空间脚本另需 FFmpeg/FFprobe（可配置 `FFMPEG_EXECUTABLE`、`FFPROBE_EXECUTABLE`），默认使用隔离测试页与 5193 端口，不能指向正在运行的生产服务。

| 实际场景验收 | 必须观察的结果 |
| --- | --- |
| 真摄影＋独立地下桩基/承台 | 开挖后结构可见，关闭恢复摄影；独立结构位置、材质、选择与编辑保持原状 |
| 土壁及坑底 | 顶视、斜视、低视角均核对接边；有效保留区不被填掉；自定义贴图正确重复，无共面闪烁 |
| 树木/堆土压平 | 只作用于确认选区；边界外摄影和独立铁路/机械对象保持原状态；关闭恢复原凸起 |
| 多项方案与旧临建 | 独立启停、删除、临建总开关及旧剖切冲突均符合所有权；重叠新方案明确拒绝；旧地下裁剪停用但仍占有集合时提示重新加载摄影，不强制接管 |
| 故障与取消 | 采样缺失、超限、超时、加载失败、存储配额不足均保留原效果；取消无晚到结果；可继续其他旧功能 |
| 生命周期与权限 | 刷新、隐藏摄影、卸载/重载、摄影变换、切换项目/账号及撤销权限；旧项目任务不得写回新上下文 |
| 视频 AR | 面板、实时融合、缓存预览、空间拾取和导出分别检查；退出或失败后地表及旧场景状态恢复 |
| 性能与资源 | 同设备、同真实模型、同相机序列比较 v1.2.2；记录采样数、输出量、耗时、交互帧时间及重复启停后资源占用 |

逐项登记通过、失败、跳过或未执行，保留日志、截图及硬件/浏览器信息。CPU、DOM、合成 WebGL、软件渲染和用户真实项目验收分别记录；任何层级不能替代其他层级。存在功能回归或相关本机验收未完成时保持待验证状态，不切换正式运行版本。

## 8. 部署及回退

保护 GitHub 的 `v1.2.2` 标签和用户未提交改动，核实实际运行源码、构建哈希、原访问地址、端口和数据根。2026-11-13 用户已授权本机 Codex 验收后部署，并明确禁止在本机新建备份；只允许 GitHub 代码备份，具体步骤见 [本机部署任务](../../CODEX_LOCAL_DEPLOY_SURFACE_EDIT.md)。现有运行目录保持可用至切换，不额外复制为备份。源码分支保存不等于用户电脑已经更新。

运行中停用地表方案即可撤销其场景效果。代码回退从已核实的 GitHub 引用恢复并重建、适配对应启动身份；现有未改动的运行目录可继续使用，不新建本机备份，不以旧数据库覆盖新增业务数据；本模块新增的参数键和贴图记录另行保留，旧版不读取它们也不应删除它们。原模型、工程数据、SDK 配置、账号权限和浏览器其他存储继续保留。公开提交只含源码、文档和脱敏验证摘要，不纳入现场摄影、设计模型、视频、私有配置或真实业务数据库。
