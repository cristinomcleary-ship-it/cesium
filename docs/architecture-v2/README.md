- 当前交付：架构设计与 Codex 实施任务书；未修改业务运行代码，未部署本机。

## 设计原则
1. 六大功能中心：工程场景、项目管理、安全管控、施工管理、智能监测、智能巡检。
2. 场景是统一空间工作区，不是某个业务模块的私有页面。
3. 原始资源、业务对象、场景实例、实时观测和业务事件分离。
4. 保留既有业务能力，通过适配器逐步接入，不一次性重写。
5. 先整理导航和呈现，再处理数据模型；持久化变更必须迁移、回滚和兼容。
6. 显隐、实例卸载、实例删除、业务对象归档、原始资源删除是不同操作。
7. 所有专业模块共用当前项目上下文、权限上下文和唯一 Viewer。
8. 未经真实浏览器和数据回归，不得宣称部署或验收完成。

## 代码审计依据与限制
本设计基于指定 Git 基线的仓库树、README、src/main.ts、src/managementStudio.ts、src/managementWorkspace.ts、src/panelCategories.ts、src/sceneDisplayPanel.ts、机械与营业线安全类型、临建设施代码、基坑监测代码及管理业务表单/功能目录。

已确认：
- src/main.ts 仍包含原始工作台顶部多标签入口，包括总览、电子沙盘、CAD、模型、临建、机械、营业线管控、倾斜摄影、GIS、视频 AR、标绘、基坑监测、三维汇报等。
- ManagementWorkspace / ManagementStudio 是另一套项目统筹工作区，含项目驾驶舱、计划进度、现场管控、巡检监测、资源保障、资料协同。
- SceneDisplayPanel 已有场景显示目录、搜索、按类型、自定义分组、批量显隐能力，可复用。
- panelCategories.ts 已有 CAD、模型、倾斜摄影、视频 AR、标绘、基坑监测、电子沙盘等面板折叠分类。
- TemporaryWorksPanel、MachineryPanel、RailSafetyPanel、FoundationPitMonitoring、视频 AR、CAD/GIS 等专业能力已分别存在，应通过适配而不是复制实现。

重要版本核对：指定提交 package.json 的版本字段为 1.2.0，依赖声明包含 Cesium 1.144.0；用户所称 1.1.0 是当前运行功能基线称谓。Codex 开始工作前必须核对本机实际部署提交、分支和工作区状态，不得仅凭 package.json 版本字段覆盖用户的运行版本认知。

本设计不是完整逐行安全审计。第一阶段 Codex 仍须完成全量符号、入口、事件、存储、接口、权限和测试映射，并修正本设计中的待确认项。
