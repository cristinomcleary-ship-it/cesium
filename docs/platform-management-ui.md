# 管理工作台界面接入与验证

本界面按 `Cesium_Codex_Design_Kit` 的浅色管理工作台、深色三维展示和 13 张状态参考增量接入原项目。`ManagementStudio` 负责管理 UI；`ManagementWorkspace` 与原 `SafetyWorkspace` 负责唯一 Viewer、空间编辑、实际视频和严格模型取点。此文说明 UI 交付范围，不替代真实项目验收。

## 修改与接入位置

- `src/managementStudio.ts`：六固定导航、列表、详情、表单、筛选、资料原件、报告快照及宿主事件。
- `src/managementStudio.css`：使用设计包色值、密度和响应式断点；样式以 `@scope (.management-studio)` 隔离。显式复位原平台 `.panel`、`.primary`、`footer` 和 `details` 以保留现有平台样式。
- `src/management/forms.ts`：83 个真实命令的字段、关联来源和权限信息；包含施工前、质量、安全与正式验收检查类别。
- `src/management/features.ts`：48 项需求的入口目录元数据，不包含示例业务记录。
- `public/management/fonts/`：设计包自带 Noto Sans SC 字体及 OFL 许可；页面从 `/management/fonts/fonts.css` 加载本地字体，无第三方字体请求。

管理界面 1920 宽使用 64px 顶栏、192px 导航、480px 抽屉；1366 宽为 56px、152px、420px。三维左右栏分别为 304/336px 和 264/300px。手机提供我的任务、进度填报、问题反馈和资料查看；表格转换为任务卡，表单抽屉占满可用宽度。

## 使用入口

固定模块为项目驾驶舱、计划进度、现场管控、巡检监测、资源保障、资料协同。页面主操作对应当前模块，更多操作提供专业新增入口。功能目录列出 48 项需求，进入相应清单、详情或原平台工具。

- 项目驾驶舱：实际指标和统计依据、当前任务、准备条件、协调事项、搜索、工作视图。
- 计划进度：任务、周承诺、甘特、基线；甘特条支持拖动预览，新日期必须在原任务表单确认保存后才生效，不改批准基线；功能目录另提供工作包列表及编辑。
- 现场管控：任务执行、施工日志、实绩审核、检查、问题整改、用户手工空间对象和行动项。
- 巡检监测：任务和成果、已有录像、航迹校准、媒体取证、真实监测读数、人工照片对比。
- 资源保障：准备要求、班组机械、材料批次和收发修正、检验报告、使用追溯和 JSON 台账导出。
- 资料协同：文件版本、报审、有效发布、技术答复、变更、会议、独立资料锚点、固定报告归档。

普通列表或模型选择只同步对象。点击“定位”才请求镜头移动；没有有效关联位置时禁用定位并说明原因。任务详情固定为概况、执行记录、准备条件、关联资料和操作历史。施工日志支持不计量执行说明，不通过虚构零数量实绩替代。

照片对比使用两份已归档原始图片及其来源，供人工检查，不自动判定质量或进度。报告导出为服务器保存的固定 JSON 快照；未实现 PDF 排版输出。缺少批准基线或数量权重时指标显示待配置，不把无适用数据显示成 0%。没有历史确认快照时不绘制推测趋势。

## 数据与宿主契约

业务接口为 `GET /__management/state`、`GET /__management/metrics`、`POST /__management/commands` 和原始文件上传接口。命令使用真实修订、幂等键和服务器会话权限。专业角色与所访问任务范围由服务端确认；前端不模拟角色。

`ManagementStudio(host, options)` 暴露 `videoHost`，以及 `setVisible`、`setViewMode`、`updateSceneContext`、`setExternalSelection`、`getSceneStageRect`、`getSnapshot`、`getSession`、`getSelectedRecord`、`getSelection`、`evidenceCaptured`、`anchorPicked`、`dispose`。

- `videoHost` 是稳定 DOM，由宿主移动既有视频节点接入，不创建第二视频解码器。
- 每次媒体时间更新只更新时钟和控制条；结构签名变化才更新场景面板，表单不会因逐帧数据刷新而重建。
- 时间轴只在视频工作区打开时显示；媒体秒与业务日期 D、确认截止 F 分开。F 保留秒精度，提交时转换为带时区 ISO 时间。
- 书签来自宿主 `getCameraSnapshot`，保存真实镜头与模型版本；模型锚点由严格取点结果提供。
- `evidenceCaptured` 保留宿主冻结的 `record.taskId`，不以稍后选中任务覆盖来源。
- `onViewMode` 和 `onBeforeNavigate` 可拒绝切换，宿主处理未完成几何草稿；普通表单自行提供继续编辑、保存草稿、放弃修改三选。

保存失败保留输入和上传结果；版本冲突显示服务器与当前输入差异，必须显式采用最新修订后重试。没有修改的失败重试保留幂等键；修改字段或多选后更新幂等键。文件条目已保存但版本提交失败时说明部分结果，并保留后续重试上下文。

## 独立 UI 验证

命令（从项目根目录执行）：

```powershell
node node_modules/vite/bin/vite.js --config tools/vite.management-ui.config.mjs
node tools/verify-management-ui-dom.cjs
```

专用服务端口为 5221，禁用大型目录监听。更新源码后需重新启动该测试服务才能读取新模块。测试启动 Edge，禁用 GPU；页面没有 Cesium Viewer，API 为明确标记的隔离测试响应，不修改真实项目台账。

验证结果位于 `output/management-studio/ui-dom/report.json`，包含 50 项断言、源码 SHA-256 与实际 DOM 截图。覆盖 1920×1080、1366×768、390×844、85 表单挂载、五任务详情页签、普通选择不飞镜头、初始无时间轴、503 留稿、脏表单三选、409 差异与显式重基、多选幂等键、30 次媒体更新保持视频宿主和草稿、复检准备状态、重复整改入口、发布版本作废、监测 samples、逐检查项证据及取证任务来源，以及实际鼠标拖动甘特条后只预填日期、取消预览保持原计划和基线，以及空间对象真实修订号和历史未编号的分开呈现、真实扁平报告回执十项指标与固定20%确认进度（不被当前90%覆盖）的回归，并验证五专题图例和金色独立含义均位于侧栏、不侵入中央场景。

这些检查证明 UI 层合同和隔离交互，不代表 48 项业务均已完成实际项目验收，也不代表真实模型、视频漫游、工程坐标或人工几何已通过现场验证。真实 Viewer、持久化接口、账户权限和操作录像以主验收报告为准。


## 真实管理页面扩展验收

另使用 `tools/verify-management-extended.cjs` 从实际 `src/main.ts` 的 `/?screen=safety` 入口运行，5222 服务指向全新管理、空间与资料库目录。Edge 禁用 GPU，模型请求被拦截，因此只验收管理业务和真实后端持久化，不据此宣称三维表现通过。

已通过 A07 甘特取消/确认与基线不变、A08 未审/退回修订保持20且确认后30替代旧量、A09 周承诺与原期限保留、A10 复制检查清空签认、A16 资料新版/固定引用/解除引用/答复和变更、A17 固定报告保持原20%、A18 双真实页面409冲突留稿与显式采用新修订后保存。共8组检查（含实际入口），39次真实命令回执，页面运行异常0。

一次 `document.version` 脚本入口辅助跳转已明确保存在报告中：原脚本从模块更多操作查找按钮，未先打开资料详情。随后 `tools/verify-management-extended-entry.cjs` 使用全程实际点击验证“资料协同→资料记录→上传新版本”，自动关联原资料编号并取消，新增后台写入为0。原辅助记录未删除。

证据为 `output/platform-management/actual/extended-management-report.json`、15张 `extended-*.png` 和 `extended-management-business.mp4`（1920×1080 H.264，57.708秒；24fps为编码帧率，不是场景性能指标）。


## 最终补齐的管理操作

- 我的工作按逾期、今日和未来7天到期筛选；项目统筹按本周/下周查看任务与同范围节点，无日期记录仅列在全部视图。
- 重点事项仅按正式 `duplicateOf` 核查关系汇总重复事件，临期审批读取待审版本的实际期限，另列临期技术答复和未完成协调行动。
- 保存工作视图同时保留模块、页签、筛选、业务/确认截止、选中编号、专题、图层和界面模式；恢复先由现有场景适配器核验模型版本、权限与图层，再应用界面状态。
- “计划进度→更多操作→批量安排作业”先生成任务日期/负责人预览，再逐条以各自修订号保存。503或409保留失败项，重试不重复成功项；冲突须明确采用服务器修订。
- “资源保障→更多操作→复用任务需求清单”从已有任务向其他任务复制为新的待确认需求，需填写新需用日期，不继承签认、批次及确认依据。
- “资源保障→实际投入”人工登记人员班组或机械实际数量、业务日期、起止与说明，独立确认；不推导为自动考勤、不修改计划占用或资源准备确认。授权导出含实际投入台账。
- 首页四卡按后端稳定编号读取总体进度、延期任务、资源未齐任务和待协调事项；原十项统计公式保留。下钻优先显示同 D/F 的冻结记录，查看当前对象另用明确按钮。

新增隔离 DOM 命令为 `node tools/verify-management-workflows-dom.cjs`（同5221服务），16项通过；`node --experimental-strip-types --test src/management/workflows.test.ts` 的8项逻辑测试通过。原DOM50项通过，已扩展为85表单。
