# 三维渲染稳定性修复与现场核验

本补丁基于 `codex/machinery-integration-20261013` 的 `b6954444b276156d38708f4fa274f89ce69329c7`，保留已集成的 CAD、机械、安全管控、沙盘、视频融合和项目管理模块。Cesium 及其他依赖版本未变更，业务数据结构未变更。

## 已确认的现场错误与几何内存修复

展开后的错误为 `RangeError: Array buffer allocation failed`，调用链为 `new ArrayBuffer → new Float64Array → PrimitivePipeline.packCreateGeometryResults → Workers/createGeometry.js`。这定位到 CPU/Worker 的几何结果打包分配，不能等同于 GPU 纹理错误。

已安装的 Cesium 1.144 / engine 26.2 会在原始几何属性数组仍存在时将结果再打包为 Float64Array。旧 CAD 分组只限制待分组缓存和图元个数：已发出的 Primitive 可同时编译，超大单条线还能绕过顶点缓存阈值整条提交。任务处理器没有提供适用于本平台的在途预算。因此限制图元数量或每隔若干对象让出一帧，并不能限制几何打包的峰值内存。

修复在原 CAD 加载入口使用按显示模式设置的顶点预算：绝对高程折线每批最多 8192 点，贴地/模型依附折线每批最多 1024 点。共享场景队列同时最多编译两个 CAD Primitive 批次，生产端等待空位再继续。连续长线分片保留接头上下文和全部业务顶点；拾取仍指向原 entityIndex，各渲染分片有独立 ID。复杂面保留原有完整边界；超过普通预算的单面单独发出并独占编译，避免为了分块改写面形或新增拒绝原图纸的限制。AR 表面采样也按总顶点组批，超长单条独立采样，保持既有单线加密保护。

编译失败、取消和销毁只清理本次尚未完成的图层。正常取消后，已开始的 Primitive 仍占编译名额，直到 Cesium 离开在途创建/合并状态；不宣称能取消底层 Worker。Cesium 单个 Primitive 内部可分派多个 Worker，且其 Promise.all 会在首个失败时提前拒绝，因此“两个批次”不等于“两个 Worker”，失败后也不宣称所有底层任务已结清。

普通加载、资料库恢复、AR 临时 CAD 副本共用该入口；隐藏的 AR 副本也能在不显示内容的情况下完成编译。导入完成以全部新图元已准备好为准，而非仅把描述对象加入场景。

同版本 Cesium 的 `createGeometry → packCreateGeometryResults` 合成对照：

| 样例 | 原单次打包缓冲区 | 修复后最大单次打包缓冲区 |
| --- | ---: | ---: |
| 绝对高程，10 万点折线 | 39,999,896 B | 3,276,696 B，下降 91.81% |
| 贴地，1 万点折线 | 26,557,880 B | 2,717,624 B，下降 89.77% |

原始逻辑顶点、线段及图元数均保留。这是单次打包缓冲区的对照，不是浏览器总内存或现场故障率指标。复杂单面本身仍可能超过设备内存；本补丁不降低其精度或擅自删面。传统 GLB 兼容 Entity 路径与其他 GIS 渲染不属于该 Primitive 队列范围。

## 同时修复的生命周期问题

1. **释放后的着色器重新进入渲染。** AR 透明度和遮挡功能暂时接管模型 shader；原模块在此期间释放旧 shader 后，退出 AR 会将已销毁的旧对象重新挂回。实际 Cesium `CustomShader` 可复现 `This object was destroyed`。恢复前现在检查旧 shader 是否仍存活，保留其他模块新设置的 shader。失效的临时覆盖不会复活，模型继续采用其原始材质。
2. **恢复操作误关健康裁剪。** 任意销毁对象异常都会调用地下工程恢复，旧逻辑即使没有失效裁剪也会取消剖切、开挖勾选并关闭健康集合。现在只清理损坏引用，并为本工具拥有且仍开启的损坏对象按原配置重建；健康对象和其他模块的有效替换保留。正常瓦片内容在下一次更新重新关联到新集合。如果 Cesium 已将受影响瓦片内容标记为失败，则明确停止自动恢复并提示重载对应资源，不把缺失瓦片的一帧误报为恢复成功。
3. **恢复调度误报成功。** 旧逻辑在未修复任何对象时仍定时重启，定时器也可能在新的致命异常之后重新启动场景，且未等有效帧就提示已就绪。现在仅在实际修复后恢复；新异常取消旧任务；连续恢复有次数限制；成功以真实 `postRender` 为准。异常恢复不再修改相机输入开关或取消相机飞行。

错误面板直接显示转义后的异常摘要，完整堆栈仍保留；现有诊断记录增加当前模块和画布尺寸。未知异常保持可见，不统一吞错、自动刷新或重建 Viewer。
