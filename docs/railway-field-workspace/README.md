# 邻近营业线三维工作台

本页记录 2026-10-14 版。最新布局与资料联动流程见 [2026-10-15 版说明](20261015-design.md)。

本轮按已确认的现场 Demo 重组现有平台。入口为 `?screen=management`，原 `?screen=safety` 和启动脚本继续适用。使用现有模型、机械资源、铁路限界、防护人员、真实录像、问题和权限数据；未导入 Demo 示例记录。

## 页面与操作

主导航为 **现场工作台、巡检与问题、项目资料**。计划、资源、任务、今日管控等已有业务保留在顶部“更多业务”。已有 `safety:project` 项目、具备模型权限的账号默认打开现场；其他项目和无模型权限账号保留业务页面，不展示无权限的模型。

现场保留原 Cesium Viewer。左侧对象目录列出当前账号可见的全部机械，包含未布置机械，按资源编号去重；也提供铁路限界、防护人员与工点入口。顶部可选择工点和作业，查看机械无需先建立作业卡。

右侧只有三个页签：

| 页签 | 用途 |
| --- | --- |
| 对象操作 | 点选机械后定位、调整布置、倾覆分析、查看交叉结果并登记问题。原有编辑器在同一面板中打开。 |
| 显示管理 | 复用原有类型目录和自定义分组；显示隐藏、标签、颜色、透明度及动态效果沿用已有能力和偏好。 |
| 现场问题 | 查看当前机械或全部现场的未闭问题，打开原办理与复核抽屉，回到问题关联机械的当前位置。 |

机械倾覆分析继续使用原模型几何、当前角度投影和既有倾覆演示。没有模型、参数无效、缺少所选限界、配置冲突、未保存预览或正在计算时，显示明确的待核实状态；不会将它们解释为安全。隐藏对象只控制画面，不关闭风险计算。关闭问题不消除仍存在的几何交叉。

登记机械筛查问题继续采用服务器保存的来源修订和冻结证据。回到现场定位的是当前机械；当前修订变化时给出提示，历史来源继续留在问题详情中。机械已删除、未布置或不可见时，不能伪造一个可定位位置。

## 可选作业卡

“为此机械建作业卡”预填机械，当前选择的工点可带入作业。首屏集中显示名称、负责人、作业窗口、机械和工点，其他计划字段折叠。草稿只需作业名称；正式发布、开工、暂停恢复、收工和归档仍按已有权限及条件流程办理。

`task.create` / `task.update` 新增可选 `resourceIds: string[]`。仅允许当前项目、当前账号可见的机械设备；去重保存，省略字段保留原关联，传空数组解除关联。关联只写入任务，不改变机械位置、限界选择或机械管控配置的任务归属，也不自动满足开工条件。共用机械的可见范围沿用“所有关联任务均获授权”的既有保守规则。

人员定位接入本轮继续暂缓。保留人工防护人员及工作区域布置；历史设备配置收入高级选项，原工作台的既有能力不删除。

## 数据与部署

保留管理数据库、附件、模型及账号。更新包含前端和管理后端，不能只替换静态页面。部署前先停服务并备份实际数据目录，再合并源码、构建并重启原服务。开发环境使用项目原依赖和 Node.js 24，执行 `npm run dev -- --host 127.0.0.1`，访问终端显示的实际端口。

自动验证及待完成的浏览器验收见 [validation.md](validation.md)。本轮没有改用 Demo 中的简化模型算法，也没有新增定位网关功能。
