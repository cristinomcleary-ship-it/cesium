# 现场工作台卡顿与倾覆演示修复

日期：2026-10-15。基线版本：`49f8ed0`。

## 修复内容

- 不再因为镜头变化、暂停视频时钟或模型质量计数变化，每秒多次重建机械属性和右侧编辑面板。项目修订、权限、账号和页面状态变化仍会同步。
- 地下工程工具只在明确取点期间启用透明表面深度拾取，完成或异常后立即恢复；普通镜头操作不再额外渲染透明安全范围。
- 软件渲染器（如 SwiftShader）使用轻量镜头导航，避免拖动、缩放时同步读取 GPU 深度导致页面长时间无响应。导航支点采用地形／椭球；机械布置、模型表面取点和实际坐标不受此开关影响。硬件渲染和实体跟踪保持原导航路径。
- 机械对象卡直接显示“三维倾覆演示”。点击后先定位机械，再加载实际模型并自动播放；可暂停、调角度、复位和退出，关闭或切换对象后迟到的加载不会恢复播放。
- 修正从三维安全范围选中机械时资源 ID 与配置 ID 混用的问题；机械参数、倾覆分析和对象资料保持选择一致。

## 使用方式

进入“现场工作台”，在右侧对象目录选中已布置的机械，点击“三维倾覆演示”。演示使用只读模型副本，不保存倾倒姿态。当前机械隐藏时会提示先在显示管理中显示；未布置机械会提示先完成布置。

## 性能定位与验证方式

使用隔离项目、内置吊机／挖掘机／桩机真实 GLB 和铁路限界，通过 Chromium 的实际鼠标拖动与滚轮操作验证，并记录主线程长任务、100 ms 心跳、业务同步次数和 CPU profile。没有用静态截图代替移动验收，也没有写入正式项目数据。

初始版本相同 25 步拖动与 4 次滚轮操作中，最长页面阻塞约 13 秒。移除反复业务同步后仍有阻塞；CPU profile 将主要时间定位到 Cesium 相机的 `readPixels`。仅关闭透明深度或开启按需渲染都不足以解决，因此没有把这两项试验当作最终通过依据。全局按需渲染也可能影响旧标绘动态效果，本次保持原渲染方式。

软件渲染器的导航兼容处理只作用于当前相机控制器同步更新调用，使用 `finally` 恢复原深度设置。此处适配仓库固定的 Cesium 1.144 内部 `update` 方法，安装前检查方法存在；升级 Cesium 时需重新执行镜头与精确取点回归。不能只因浏览器自动化总耗时降低就宣称真实工程帧率提升：SwiftShader 的光栅化和自动输入调度仍明显慢于硬件 GPU。
