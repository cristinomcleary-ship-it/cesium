目标：形成能够支撑工程现场使用的数字孪生工作台，提升业务可靠性、操作效率、三维清晰度和视频融合可信度。

## 1. 执行范围与版本核对

按 A「可靠性修复」→ B「工作台与视觉」→ C「三维与视频融合」顺序实现。先阅读当前 AGENTS.md、启动说明、数据说明及本任务书，再核对实际分支、HEAD、未提交改动与运行入口。

审查基线用于定位问题，不要求回退到该提交。若当前 HEAD 已更新，应先确认问题是否仍存在；已修复项保留实现与证据，未修复项在当前工作基础上处理。文件行号可能变化，应以函数、命令名称定位。

本任务书是执行方案；其中“已复现”指审查时对原始模块进行隔离逻辑复现，不代表生产接口或真实 GPU 场景已经复测。AR 状态来自仓库记录，执行时须检查最新状态。

执行要求：

- 使用独立功能分支或工作区，保留用户未提交改动；禁止强制覆盖现有工作。
- 保留真实账号、SQLite、审计、幂等、修订冲突、冻结报告、空间来源校验与唯一 Viewer。
- 保留工程文件、稳定业务 ID、模型坐标、视频来源和历史报告。测试使用隔离业务目录，真实模型和录像作为只读来源。
- 需要数据库迁移时，先提供迁移脚本、备份和恢复办法，在副本上验证；生产数据迁移作为单独的部署步骤。
- 不进行与目标无关的框架替换、依赖批量升级、引擎迁移或整个项目重写。按功能边界做必要拆分。
- 各批独立提交、独立验收。出现某项输入缺失时，完成其他可实施工作，并准确列出该项缺什么、如何取得。
- 不把设计示例数据写入正式项目；不以合成场景、DOM 测试或构建成功替代真实工程精度验收。

## 2. A 批：业务可靠性修复

### A1. 统一记录与关联对象权限

优先文件：
- server/management/domain.ts：load、taskAccess、validateLinks、命令处理。
- server/managementStore.ts：execute、记录查询、命令上下文、文件读取和冲突响应。
- server/management/ 下适用的权限与证据模块。

已确认问题：load 只检查单个 taskId，未完整检查 taskIds；修订冲突先于授权返回 current。真实服务调用链没有额外的目标任务范围过滤。

实现：
1. 抽取共享的对象授权规则。身份认证、项目成员资格、目标记录范围、关联目标范围须全部通过。
2. 覆盖 taskId、taskIds、资料版本、附件及引用目标；创建、修改、发布、导出、批量命令、连带更新使用同一规则。
3. 更新时同时检查旧对象范围和新关联范围，不能通过修改关联把记录转移到未授权任务。
4. 在版本检查、状态错误和差异输出之前检查授权。未授权响应不得含名称、正文、附件地址、修订内容。
5. 明确定义未设置任务范围与空任务范围的区别，避免空数组被解释成全项目授权。
6. 保留原角色权限，不以客户端传入身份或隐藏按钮代替服务端授权。

验收：
- 在隔离服务中创建任务 A/B 和各自受限账号。
- A 账号不能读取、修改、发布、关联或导出 B 记录；知道 B 的 ID 也不能通过。
- 对 B 发送错误 revision，返回拒绝且不泄漏 current。
- 验证真实 HTTP 入口，不只验证辅助函数；有权人员正常操作不回归。

### A2. 修复检查清单完整性

优先文件：server/management/domain.ts 中 check.create、check.copy、check.record、check.confirm。

已确认问题：只检查数组长度及每个 ID 是否存在；重复提交一个通过项可替代另一个必检项。

实现：
1. 创建和复制检查清单时保证 ID 唯一；绑定清单或模板版本。
2. 填报时要求 ID 集合与该版本原清单完全一致，拒绝重复、缺失和未知 ID。
3. 使用服务器保存的名称、必检属性及适用规则；客户端只提交允许修改的结果、依据、证据等字段。
4. 可接受无害的提交顺序变化，但按服务器原顺序保存，不能因重排漏项。
5. “不适用”遵循已配置规则并填写依据；待核实项不能被算作通过。
6. 保留“检查已完成”和“检查通过”两个不同结论。

验收：
- 原清单包含普通项与关键项，提交两个相同普通项必须被拒绝且数据不变。
- 漏项、额外项、伪造 required、未知版本均有明确反馈。
- 必检项不通过时，允许按业务规则记录不合格结论，但 satisfied 必须为 false。

### A3. 建立可配置的开工与完工条件

优先文件：server/management/domain.ts、src/managementTypes.ts、src/management/forms.ts、src/managementStudio.ts。

已确认行为：task.start 未完整核对实际前置状态、待确认开工检查和必备资料；task.confirm-completion 主要依据任务状态流转。

实现：
1. 定义条件类型：强制、提示、不适用；覆盖工序前置、施工前检查、资源准备、有效资料、外部许可、验收和阻断问题。
2. 按任务/工序配置适用规则。已明确为必备的条件不得静默放行；历史记录缺少规则时显示待配置，不能自动标为满足。
3. 服务端在状态变更事务中重新检查条件；前端展示逐项原因及可跳转处理入口。
4. 保留有权人员的例外放行能力，记录规则版本、具体豁免项、理由、依据和签认人。
5. 完工区分数量任务、里程碑、非计量任务；不得统一规定“必须100%计量”，不得把计量100%直接视为质量验收通过。
6. 状态变更和准入判断使用同一有效数据版本，处理并发变化。

验收：
- 已配置强制前置未满足、必检未确认、必备资料未发布时，开工被阻断。
- 配置为阻断的问题未关闭时，任务不能普通确认完成。
- 授权例外放行可追溯；普通执行账号不能自行豁免。
- 非计量任务按其验收规则完成，避免被数量字段错误阻断。

### A4. 统一地图事件与管理问题生命周期

优先文件：server/safetyEventStore.ts、src/safetyEventTypes.ts、src/safetyEventValidation.ts、server/management/domain.ts、src/safetyWorkspace.ts、src/managementWorkspace.ts。

已确认问题：旧地图事件可直接完成，而管理 issues 有指派、整改、复核流程；两者关闭规则不一致。

实现：
1. 选定管理问题生命周期作为新事件的权威状态来源。
2. 从模型、录像、检查发现问题时创建同一业务记录，并保留发现位置、空间修订、媒体时间和证据来源。
3. 地图与管理列表读取同一状态；执行人员提交整改，由有权复核人员通过或退回。
4. 旧事件通过明确关联或兼容适配接入，保留原 ID、历史状态及来源，不伪造历史复核记录。
5. 对证据核验真实存储、权限与关联，不仅校验附件 ID 是字符串。
6. 跨存储同步须可恢复、可重试且幂等；不能以两次独立写入都“通常成功”当作事务保障。

验收：
- 地图创建的问题在管理列表中只有一个权威记录。
- 提交整改、退回、再次提交、通过后，两端状态一致。
- 不存在或无权访问的附件不能引用；重试不会重复生成事件。
- 历史事件仍可查阅，新流程适用范围明确。

### A5. 修复统计状态与资料分类

优先文件：src/managementStudio.ts 中 loadMetrics、kpis、sortedRows、folderTree、document-filter、日期及筛选事件。

统计实现：
1. 以项目、业务日期 D、确认截止 F、筛选组合标识请求上下文。
2. 上下文变化后进入加载状态，旧数字不得冒充新上下文结果。
3. 请求失败显示持久的失败/过期状态及重试入口；保留上次数据时必须明确原日期与范围。
4. 丢弃过期请求结果；统计下钻、报告和导出使用一致上下文。
5. 对未配置、无适用数据、真实零值、请求失败作不同展示。

分类实现：
1. 增加独立 category 筛选字段，按资料 category 匹配。
2. 搜索词与类别、状态组合使用，点击类别不覆盖用户的搜索词。
3. 显示选中类别、匹配数量、清除筛选入口。

验收：
- 切换日期后注入一次503，旧指标不能显示成新日期统计。
- 快速连续切换日期/筛选，迟到响应不能覆盖最新上下文。
- 中文名称、category=drawing 的图纸能通过“施工图纸”筛选；安全资料不混入。
- 空数据、未配置和失败状态有不同反馈。

### A6. 让受限现场人员能使用授权附件

优先文件：server/managementStore.ts、server/management/libraryPermissions.test.ts、适用的资料引用及证据模块。

实现：
1. 授权附件访问依据其任务关联与明确资源权限，不能因为设置任务范围而一概禁止查看自己的证据。
2. 原件、预览、下载链接采用一致授权；更换账号或权限后清除越权缓存。
3. 全项目3D Tiles的授权与任务附件分开定义；前端裁剪或隐藏不能当作模型数据隔离。
4. 只允许当前授权资料引用，不为“让链接可用”开放整个资料目录。

验收：
- A执行人员可上传、关联、查看A的照片/图纸；不能通过直接地址读取B附件。
- 权限变更后旧链接重新校验；后台原件和预览不存在绕行路径。

## 3. B 批：工作台体验与美观性

总体设计：延续六模块导航与“浅色管理、深色三维”；以工程对象及待办为中心。业务文字优先于装饰，模型优先于空面板。

### B1. 建立统一的版式与样式变量

优先文件：src/managementStudio.css、src/managementStudio.ts、src/managementWorkspace.css，以及实际生效的公共样式。

建议设计参数：
- 桌面正文14px、表格13–14px、辅助文字至少12px；页面标题22–24px。
- 间距采用4/8/12/16/24/32px；表格行高舒适档44–48px，紧凑档按可读性另设。
- 浅色背景 #F3F6F9、卡片 #FFFFFF、主文字 #173041、次文字 #526878、操作强调 #128AA5。
- 三维界面采用深蓝背景，卡片保持足够不透明度；常规文字与背景对比以4.5:1作为内部设计目标。
- 状态色在表格、图例、图表和模型中一致；选中使用独立描边/图标，不仅靠风险色变化。
- 将关键尺寸、字体、颜色提取为一组设计变量；避免不断追加覆盖规则导致各页面不一致。

### B2. 扩大三维有效区域

实现：
1. 默认进入三维时收起未选对象的右侧详情；选中对象后再展开。
2. 左侧提供对象树、搜索和筛选；左栏约240–280px，右侧详情约320–360px，并可分别折叠。
3. 1366×768未选对象时，中央三维有效宽度目标不低于65%。
4. 超过摘要条数时显示“已显示/总数”和“查看全部”；任意工点可搜索定位。
5. 普通选择仅同步高亮和详情；显式“定位”移动镜头，提供返回上一视角。
6. 绘制、测量和视频工作区按任务显示工具，避免同时占满中央场景。
7. 保留单一Viewer；切换页面时不重建模型或重复注册交互。

验收：
- 1920×1080、1366×768及125%缩放无关键按钮被遮挡。
- 未选对象没有固定空详情栏；20个以上对象均可查找。
- 打开详情、视频、绘制工具后仍能操作目标，不发生相机控制冲突。

### B3. 以工点组织业务操作

优先文件：src/managementStudio.ts、src/management/forms.ts、src/managementWorkspace.ts、关联与空间对象模块。

实现：
1. 选中墩位或施工区域后，统一展示概况、任务、资料、资源/检验、巡检、问题、历史。
2. 按对象类型提供详情模板：任务突出责任人和下一步；风险突出位置、时限和整改；材料突出批次、检验、可用量和去向。
3. 资料关联使用可搜索选择器或场景选择，普通用户无需手抄UUID。
4. 同时提供对象→资料与资料→对象的反向关联，明确有效最新版和固定历史版。
5. 原始ID、SHA、JSON、内部枚举放入折叠的数据来源或技术详情。
6. 未保存确认优先引导保存或继续编辑；放弃采用低强调危险按钮，补齐焦点进入、循环与返回。
7. 原有权限、来源和版本规则继续由服务端核验。

验收：
- 实际完成“选工点→查任务→打开图纸→关联试验报告→登记问题→指派整改→提交证据→复核→刷新查看”。
- 不依赖手输内部ID；解除关联不删除原文件。
- 验证保存失败保留草稿、409冲突可核对、无权记录不出现在选择器中。

### B4. 完善甘特与照片对比

甘特：

验收：在1366与1920尺寸下可同时读懂两侧信息，并完成真实操作；原件和基线不被覆盖。

### B5. 保证移动端关键操作可达

## 4. C 批：三维清晰度与视频融合

先确认主平台、旧AR和独立V2各自实际使用的路径与当前开发约束。优化必须落在用户正在使用的路径上；V2保持独立计算和结果契约，通过适配器接入。不要只修改未接入页面后宣称主平台已改善。

### C1. 明确数据与校准状态

优先文件：src/videoArCameraFrame.ts、src/videoArHeight.ts、src/safetyVideoRoamData.ts、ar_v2/ 的相机/定位/验证模块。

实现：
1. 将视频身份、PTS、轨迹时间、坐标系、垂直基准、模型变换、相机K/D、姿态定义及安装关系绑定到可追溯档案。
2. 每项标记已核验、估计、缺失及依据；界面说明缺项影响与补充入口。
3. 区分原视频播放、航迹跟随、经过验证的模型融合三种能力。
4. 缺失或退化时保留原模型与明确状态；不以估计地面替代可靠高程。
5. 不硬编码素材高差，不移动真实模型来掩盖投影错位，不放宽深度阈值制造“贴合”。

### C2. 修复有效纹理清晰度

优先文件：src/videoArFusion.ts 中 MAX_TEXTURE_EDGE、drawTexture，以及实际投影纹理适配层。

实现：
1. 将固定1024长边改为可配置、受设备能力约束的画质档。
2. 建议节能长边1024、清晰长边1920；暂停精查可使用原始分辨率，受GPU上限和内存预算约束。
3. 记录实际源尺寸、上传纹理尺寸和降档原因，不将放大的低分辨率纹理当作高清。
4. 复用GPU纹理，正确释放换源前的资源；分辨率变化后相机内参按同一像素约定缩放。
5. 控制细节放在设置或诊断中，普通用户只看到清楚的画质档与必要降级提示。

验收：同一原始4K帧、同一视角对比节能与1080p；验证实际纹理尺寸、边缘细节、显存和换源释放。

### C3. 解开4fps限制并保留同步正确性

优先文件：src/videoArFusion.ts 中 MAX_CONTINUOUS_GEOMETRY_FPS、prepareVideo、drawTexture，src/videoArModelProjector.ts，以及V2播放适配层。

实现：
1. 分别记录视频解码帧率、投影提交频率和Cesium渲染帧率。
2. 拆分昂贵的几何/深度准备、按媒体PTS取姿态、纹理上传与提交；避免所有工作共用一个4fps上限。
